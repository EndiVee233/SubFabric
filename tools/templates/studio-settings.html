双引擎分工性能测试
本机同时有 Intel NPU 与 N 卡，两个识别引擎落在不同硬件上，可以并行工作、各认一部分分片。 但速度取决于机型、散热与驱动，没法靠猜 —— 这里在你的机器上实测，给出该用多长的分片、以及最佳配比。
测法：每个分片长度先各跑一次“只用 GPU”“只用 NPU”作基线，据此推算其余配比的预期耗时， 再只把最优的那一个真跑一次验证。于是 9 次真跑覆盖全部配比，推荐值有实测背书。

调用参数
每批行数 上下文行数

每批行数：一次请求最多带多少行给翻译模型（5~100）。批越大请求越少，但译文行数一旦和输入对不上，整批都要重来；批越小越稳，请求也越多。失败时程序会自动拆成两半重试。
上下文行数：每批额外把前面 N 行「原文 + 已定译文」当参考送给模型，让它接着上文译（0 = 不送，与旧行为一致）。参考行不参与译文行数校验。

热词列表与强度需手动保存；其余增强选项修改后即时保存。

热词 一格一个单词 · ＋ 添加 · − 删除

whisper 用作初始提示词，Parakeet 用作热词加权。术语表的「原文」列会自动并进来。

你在字幕里改对过的专有名词，就是 ASR 听错的词 —— 挖出来加进热词，下次就不会再错
LLM 分角色 用视频简介推断人物，再把说话人对应到角色名
先用视频标题/简介让模型判断有几个人物，按这个人数做说话人分离；分离后把说话人换成真实角色名，没对应上的保留说话人编号。模型用「字幕翻译」里配的那份。
逐句置信度 标注每句的可信程度，供复核
置信度由三个信号融合：词级概率与音频质量在解码时白送、不花时间；稳定性要把音频加噪重跑 2 遍 —— 实测 236 秒音频 10.7s → 20.8s，约慢一倍。默认「完整」。
自动纠错 让 LLM 通读全片找"语句不通顺"
在稿件页点「反思纠错」触发。它会找出没说完 / 被硬切 / 拼接痕迹 / 疑似听错的地方，先给预览清单，你勾选后才重识别那几段。
上下文 秒／前后各取；单段上限 秒；每批 行（长稿会分批通读）

想用本地部署的模型（如 Qwen3 量化版）：起一个 OpenAI 兼容服务后，把地址填成 http://127.0.0.1:端口/v1、模型名填服务暴露的名字，Key 可留空。

重排逐词时间 Qwen3 对齐 · 文本不改

右键字幕块选「重排逐词时间」，或点「全片逐词重校对」时使用。 前提是这句文本已经确认正确：只把已有文本和原片音频交给 Qwen3-ForcedAligner 重新量时间，不跑 ASR、不改文本、不改整句起止。

对齐器只负责时间。如果这句话本身还不确定，请用独立的「重新识别」功能， 不要让对齐器去猜文本。

逐词字幕自愈

载入或导入时，若发现「逐词行的文本被清空、文本跑到了**同时间戳**的另一行上」 （旧版导入 bug 的遗留），自动把文本搬回来。正常稿件上是空转，不会误改。 关掉之后只会在控制台提示，不动稿件。
