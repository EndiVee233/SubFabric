Classic 不是一种风格，
它是一层没做完的换色

把三套主题的独占规则行数放在一起就明白了：Classic 22 行，Material You 104 行，Windows 10 694 行。 Classic 用 22 条规则去改颜色、去模糊、加阴影——它没有自己的形状、动效、版式母题， 只是把为 Studio 设计的骨架染成了橙灰。 它不是"丑在设计选择上"，而是丑在根本没被设计。

04

五个病灶

FIVE DEFECTS

每一条都能指到具体行号，不是感觉。

01明度分层失效，又没有替代方案1.06:1
1.30:1

深色下用"填充明度"分层，前提是每一级至少差 3%。Classic 的 bg-0 #0b0b0e 到 surface #131318 只差 1.06:1，#2a2a34 描边只有 1.30:1。

如果它像 UWP 那样有 2.47:1 的线，或者像 Material 那样让 surface 带一点 seed 色相，都能救。它两样都没有。

/* studio.css:3152 + JS classic 令牌 */ --bg: #0b0b0e --surface: #131318 → 1.06:1 --line: #2a2a34 → 1.30:1 /* 唯一的补充：打在近黑上的阴影 */ box-shadow: 0 2px 10px #00000030 ≈ 不可见
改法：surface 抬到 #181a20（≈1.2:1），描边抬到 #3a3a46（≈2.0:1）。
02强调色通胀：438 次引用，橙色从"指针"变成"墙纸"438
of 611

全表 var(--accent*) 共 611 次，其中纯 var(--accent) 438 次。它同时是：主按钮填充、悬停文字、边框、播放头、进度条、徽标、版本号、字标渐变、光晕。

同一个颜色承担 9 种语义，结果就是没有一种语义成立——用户看到橙色时无法判断"这是当前状态、可点、还是品牌装饰"。

/* 橙色同时出现在： */ .btn-accent background: var(--accent) .btn:hover color: var(--accent) .sf-nav a.active background: var(--accent-soft) .cue-card border-left: 3px var(--accent) #tl-cursor background: var(--accent) .pc-badge color: var(--accent) .app-logo gradient(accent → accent-2) ... 共 438 处
改法：把橙色限定到 3 类（主操作 / 当前态 / 数据高亮），目标 ≤120 处。
03淡橙叠加在近黑上会变"棕"#39241F
H20 S29 L17

Classic 的容器色是 rgba(255,122,69,.16) 直接叠在 #131318 上，实际得到 #39241F——一个饱和度和明度都很低的棕色。

棕在灰黑底上天然读作"脏/锈/旧皮革"。Material 做同一件事用的是 #223454（navy）——蓝降明度仍然是蓝，不进入"脏"的联想区。这就是为什么两块淡色容器，一块看着高级、一块看着土。

/* 同一个"低透明强调色容器"，两种结果 */ Classic rgba(255,122,69,.16) on #131318 → #39241F 棕 · 脏 Material #223454 (seed #5789dc 推导) → navy · 干净 /* 橙色在深底上还会"膨胀"：高彩度暖色 */ /* 在低亮度场里显得更亮更大，视觉上外扩 */
改法：容器色改用"降亮保彩"的实色（如 #2E1B12 再压饱和），不要用透明橙叠加。

111 decls

只统计"生产 Studio 外壳"这一段（3150–3650 行），就出现 18 种 border-radius：4 / 6 / 7 / 8 / 10 / 12 / 13 / 14 / 16 / 18 / 19 / 20 / 22 / 24 / 26 / 28 / 50% / 999px。

而 --sf-radius 这个"统一圆角令牌"在全表只被引用 1 次。所以"圆角跟语义走"是文档里的说法，代码里是逐组件手写。同屏出现 8px 卡片 + 24px 续作卡 + 28px 花朵 + 999px 胶囊 + 直角输入框，读起来就是"随机圆角"。

改法：收敛到 3 档（卡片 12 / 控件 8 / 胶囊 999），删掉 7/13/14/19/22/26 这些"顺手值"。
05它把位移动效显式关掉了，按下去没有回执transform:
none !important

Classic 不是"没做动效"，是主动删掉：一条规则给按钮、导航、页签统统压上 transform:none!important，并把过渡锁成 120ms。

UWP 也关位移，但它补了 Fluent 的按压内阴影（inset 0 1px 2px）；Material 用 spring 驱动的 scale（播放键低到 .92）。Classic 两者都没有——它是三套里唯一"按下什么都不发生"的方言。而且它把 transform 从 transition 列表里也删了，即便不加 !important 也不会动。

/* studio.css:4067 —— 一行杀掉全部按压反馈 */ .sf-studio[data-design=classic] :is( .btn, .sf-nav a, .st-tab, .ptab, ... ) { border-radius: 6px; transform: none !important; transition: background .12s, color .12s ...; } /* 且 Classic 没有任何 :active 规则 */
改法：删掉 transform:none，或用 box-shadow: inset 0 1px 2px 换一种按压表达。
05

为什么另两套能成立

WHY THE OTHERS WORK

不是"UWP 和 Material 更好看"，而是它们各自有一套可执行的一致性机制；Classic 没有机制，只有一张色卡。

Windows 10
一致性 = 强制归一

用 694 条规则把所有表面压到 2–4px 直角、统一 1px #666 描边（2.47:1）、关掉毛玻璃、关掉位移动效、悬停只用中性色。

系统蓝被锁死，用户改不了——所以它永远不会被用户搞坏。首页磁贴给了它一个可识别的版式母题。

Material You
一致性 = 算法生成

一个 seed 推出 13 个令牌 + 5 个角色容器，surface 带 seed 色相，readable() 把对比度顶到 4.6。

形状也只有两档：24px 卡片 / 999px 胶囊，加上一个会 morph 的播放键。所以它不可能出现"随机圆角"——值不是人挑的。

SubFabric Classic
一致性 = 没有实现

22 条规则，全部在改颜色和取消材质。它继承了为 Studio 设计的骨架（218px 侧栏、18px 圆角、28px 花朵、999px 胶囊），只把颜色换成橙灰、圆角改成 6/8。

结果：骨架是别人的，皮是旧的，中间没有"设计"这一层。
