一块深色的、会呼吸的字幕工作台

把注意力全部让给画面与时间码。界面只用一条橙色左线、三档灰、一档等宽数字说话。 SubFabric 不是消费级视频编辑器，而是需要连续盯几个小时时间码的工具， 所以密度高、对比低、动效短、强调色面积小——每一条都能在样式表里找到对应的取舍记录。

01

六条骨架原则

Principles

这六条不是审美偏好，而是从 studio.css 的修复记录里反推出来的稳定约束——每一条都对应过一次真实的返工。

P1

一个强调色，一条竖线

选中态用 3px 左边框表达。列表纵向滚动时，左边缘是唯一稳定的轨道；横向位移会被 overflow 裁掉。

P2

两档文字，三级层级

只有 text-0 / 1 / 2 三档灰，不做第四档。字幕色单独成令牌，与 UI 灰阶物理隔离。

P3

细线分层，不压阴影

面板靠 1px 描边加 2.2% 顶部高光分层；阴影只给真的浮起来的弹层。

P4

圆角跟语义走

6 / 9 / 13 / 18 四档加胶囊，容器越大圆角越大。三套方言各自压缩或放大这一族。

P5

动效只做"接住"

只动 transform 与 opacity。hover 抬 1px、active 缩 .97，按下去必须有回执。

P6

一套图标，一种笔触

24 网格、1.9 描边、圆头圆角、currentColor。明确拒绝 emoji——字重和基线不受控。

02

色彩

Color

底色是近黑的冷灰，不是纯黑——纯黑在长时间使用下会让 1px 描边"消失"， 而 #0b0b0e 仍能托住 #2a2a34 的分层。 强调色是指针不是底色，面积永远小于一个图标。

10

反模式

Anti-patterns

下面每一条都对应过一次真实返工——不是假想的"坏实践"，是踩过的坑。

禁忌 ── 为什么
用 inset box-shadow 画左边条
会和既有 border-left 叠成两条并排竖线，用户直接报"明显是两个竖线"
列表卡 hover 用 translateX
横向位移被 overflow 裁掉，右边框当场消失
给 #home-view 加 position: relative
它是全屏浮层，改完就盖不住编辑器，画面穿帮
给 #video-stage 改 position
丢掉 absolute; inset:0，舞台退回 300×150
组件里散写时长 / 颜色
必须走 --dur-* / --accent-aNN，否则换主题色与降动效全部失效
用 emoji 当图标
跨机器字重留白不受控，视觉重量不一致
加第四档灰
三级灰已够表达，再加就让"哪个更重要"失去答案
大面积铺强调色
强调色是指针不是底色，面积大了会盖掉时间码
