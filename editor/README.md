# SubFabric（字幕工作台）v2.1.11

基于 Web 的字幕编辑器：视频播放 + 字幕实时叠加 + 时间轴 + 编辑面板。
支持 **SRT 双语字幕**（主/副语言上下排列）与 **ASS 高级特效字幕**（libass 内核，卡拉OK/颜色/定位等特效完整还原）。

## v2.1.7 更新

- **修「新建项目 / 详细信息」里的输入框、下拉框、文本框外观与全局设置对不上**。文本域此前**完全没有基础样式** ——
  输入控件的基础规则只覆盖了单行输入框和下拉框，`<textarea>` 不在选择器里，浏览器默认外观直接透出：
  灰底、直角、零内边距、等宽字体，聚焦时还挂着一圈系统默认焦点环。现在三者共用同一套定义，逐项对齐
  「全局设置」里的同款控件：同样的底色与描边、8px 圆角、`8px 12px` 内边距、13px 字号、继承界面字体，
  聚焦换成主题色的描边加柔和外环。
- 单行输入框与下拉框补上 `font-family: inherit`（原先只是靠选择器列表里带了它们才侥幸没掉字体）。
- 文本域高度不再被面板的纵向 flex 拉伸，固定为 100% 宽 + `min-height`，仍可手动拖高。

## v2.1.4 更新

- **波形与字幕块改为重叠布局**。原先把波形「独立成带」放在字幕轨上方，既多占一整条轨、也看不到两者的叠加关系；现在波形铺满整条区域，**字幕块半透明浮在它上面**，块间缝隙露出完整波形，纵向空间共用。
- **波形高度拉伸填满**，随面板高度自适应（不再固定 72px、下面留大片空白）。同时给面板高度加了合理上下限 **132px ~ min(420px, 45% 屏高)** —— 太矮波形与字幕块都展不开，太高则块内大片留白、逐词标记离中文行太远。三条调整路径（拖分割线 / 设置滑块 / 记住的偏好值）统一生效。
- **逐词标记块放大并下移**：由 10×4 改为 **20×8**（拖动中宽 10），底部余量 2.5px 贴底但不与块边框粘连。原先小块在密集词里太难点中。
- 修一处极矮轨的绘制错位：块高 4px 时固定的 5px 底部余量会让标记被画到**块外**；现在余量按块高缩放。
- 修一处优先级弄反：标记放大后分隔线被压住，根因是让装饰性的分隔线优先于拖动抓手；现在**标记优先**，分隔线让位。
- 标记宽度改为以词起点**居中**绘制，词文本随标记半宽让位、命中区同步放大 —— 变宽后仍与词对齐、不压字、点得中。

8 个探针验证器 + 5 个测试全过。探针覆盖：波形与轨道同起点、波形填满无空白带、面板三档（132/232/420px）布局、逐词标记几何（高/宽/底部余量/不越界）。

## v2.1.3 更新

- **修：时间轴波形「看不出声音起伏」**。根因在服务端分桶，不在画图代码 —— 用固定 `+18dB` 增益把语音振幅拉起来，
  撞上 `Math.min(1, …)` 硬钳位，**实测 21.7% 的音频桶被钉死在满格**，再经 `sqrt` 把弱音整体抬高，
  弱强差异被彻底抹平。有声段动态范围只剩 4.4dB，画出来是一条实心带。
  改为**按素材自适应**：取 p99.5 分位数当参考电平归一，安静素材自动放大、响亮素材自动压小，不硬削。
  **削顶率 21.7% → 0%，渲染出的音节间隙 2 → 10、边缘锐度 0.94 → 4.7。**
- 波形改为 **min/max 双通道包络**（原来只存绝对峰值，丢掉了波形上下不对称，画出来是「条形图」而非波形），
  前端按像素列一次 path 填出整条带，任意缩放都锐利。
- 波形**独立成一条 64px 的带**（原先塞在 34px 轨道里、再被字幕块盖住，纵向只剩 26px 可用）。
- 顺带修一个隐性错位：分桶的「每桶样本数」原先按预分配容量算，而容量有 2 万的下限 ——
  30 秒音频因此被切成 20000 桶（覆盖 200 秒），**波形被压到左侧 15%、与时间轴对不上**。
  改为按真实桶密度计算。旧版本也有这个问题，只是不明显。
- 服务端两处分桶逻辑合为一份（原先 `startPrepare` 里另抄了一份，改动极易漏改一处）；
  包络格式加版本号，**老项目的旧波形缓存会自动失效重算**，不用手动清。
- PNG 兜底路径的 `volume=18dB` 同样过载，改为 `+12dB + alimiter` 软限幅。
- **逐词标记块移到字幕块底部**：原先骑在中英分隔线上，现改为贴块底（留 2px 不与块边框重合），
  与英文词文本同一行左右交错。拖动命中的容差也按块边界夹取，避免抢走相邻轨的点击。

## v2.1.2 更新

- **修：大稿件字幕列表卡顿**（5000 条时删一条字幕要卡住数秒才恢复）。实测根因**不在 JS 也不在布局，而在绘制**：`panel._render` 同步只要 65ms、强制布局 300ms、样式重算 125ms，但主线程被占住 5382ms —— 剩下 4.5s 全是绘制，因为每张卡片的 `overflow: hidden` 各自成了一个裁剪容器，浏览器要为 5000 张卡做逐卡离屏合成。

- 位置表由**实测行高**累加得出（不假设固定行高），并保留卡片 `offsetTop` 等于绝对偏移的语义，所以选中定位、跟随播放、行内编辑的定位逻辑都没有改动。

## v2.1.1 更新

- **修：删除字幕后视频区不刷新**（实测最严重时画面 20 多秒停在旧字幕上，拖一下进度条才消失）。数据与渲染轨其实都已正确更新，是**重建后的这一帧被渲染 worker 静默丢弃**：libass 重建 track 后没有"上一帧"可比对，`detect_change` 返回 0，而 worker 只在「画面有变化」时才把帧推回主线程。已在 `fetch-vendor.js` 里加一个必需的 worker 补丁，让重建轨道后强制推帧。

## 快速开始

```bash
# 1) 首次克隆后拉取渲染依赖 (libass-wasm + 中文字体, 约 19MB; 已存在则跳过)
node editor/scripts/fetch-vendor.js

# 2) 只用「创建初稿」时才需要: 建语音识别环境 (Python 3.10~3.12)
py -3.12 -m venv asr/.venv
asr/.venv/Scripts/pip.exe install -r asr/requirements.txt
#   模型本体 631MB 不入库: 首次用「创建初稿」时界面会引导你选一个空目录下载
#   ⚠ 想跳过这一整套（没显卡 / 没 Python / 不想下模型）: 初稿下拉里选「必剪 ASR（英语·云端免下载）」即可

# 3) 启动本地服务器 (支持 Range, 可直接播放本地大视频)
node editor/server.js

# 4) 浏览器打开 http://127.0.0.1:8321/  (进入项目主界面)
```

> 仓库不含示例视频与字幕（体积较大）。启动后用工具栏导入自己的视频 / SRT / ASS；
> 把媒体文件放到项目根目录，`/api/samples` 会自动列出，工具栏「示例」区一键加载。
> 旧直连 `#/editor` 仍可用（跳过主界面直接进编辑器并自动加载示例，兼容旧用法与自动化测试）。

## 云端识别（必剪 / 剪映，互为备份）

> **只支持英语**：两个云端接口都只吃英文音频，中文音频会得到无意义结果 —— 中文素材请用本地模型（Whisper / Parakeet）。
> 音频会上传到对应服务商的服务器（必剪 → bilibili、剪映 → 字节跳动），涉密素材请用本地模型。两者的结果都受服务商限流与风控影响，适合当备用而不是主力。


「创建初稿」的模型下拉里有两个**什么都不用装**的选项：**必剪 ASR（英语·云端免下载）** 与 **剪映 ASR（英语·云端免下载）**。它们把音频传给对应厂商的云端识别接口、拿回逐词时间戳，再按本项目的老规矩生成逐词 ASS —— 与本地模型走的是同一条流水线（识别 → LLM 语义分句 → 可选说话人分离 → LLM 翻译 → 逐词字幕；**语义分句对所有引擎都做**，没配 LLM 就停在那一步，见下方「LLM 分句与翻译的加固」）。

**为什么给两个**：免费云端服务普遍限次/限流，一个迟早会卡住。选中的那个失败（限流、网络、接口变动）会**自动换另一个重试**，并在日志里写清「谁失败 → 换谁」，字幕照常产出。回退只发生在**云端之间**：

- 本地任务**绝不**被悄悄改成上传（本地模型跑不动就老实报错，不会把音频传出去）
- 云端任务**绝不**自动退回本地模型（可能没装、没 GPU）
- 用户主动取消（删除项目/重跑）不触发回退
- 音频转 mp3 只做一次，换引擎时复用同一个临时文件

其他共同点：

- **零依赖**：不用显卡、不用 Python 环境、不用下载 0.6~2.8GB 模型。实测 13 秒英文音频：必剪 **2.9 秒**（4 句 / 31 词）、剪映 **3.0 秒**（5 句 / 30 词）。这两个句数是**接口原始返回**的；成品字幕的断句一律由后面的 LLM 语义分句重切，两家不再有区别
- **只做英语**：与 Parakeet / whisper 两个本地模型定位一致；识别结果进**主语言轨**，中文字幕照旧由 LLM 翻译那一步生成
- **必须显式选中**：它们**不会**当"本地没装模型"时的兜底（云端识别要把音频传出去，不能替用户默认决定），设置页里也没有下载/删除按钮
- **隐私**：音频会上传到第三方服务器（必剪 → bilibili；剪映 → 字节跳动）—— 机密素材请改用本地模型
- **都是逆向出来的非公开协议**，官方一改就失效
- 「选区重新识别」同样支持两者，也享受同一套备份逻辑（时间戳加回区间偏移）
- 项目会记下**实际**用的是哪个引擎（`meta.draft.usedModelId`），ASS 头署名与重试都按它走

## LLM 分句与翻译的加固（v1.9.0）

用户报的三个现象：**① 分句总切在半句上、断句很碎 ② 翻译偶发"失效"且原因从来定位不到 ③ 小模型被 JSON 格式带偏（每词加逗号）、思维链乱跑**。逐条对应到代码真因与处置：

### 分句（所有识别引擎都要走的那一步）

| 现象 | 真因 | 现在 |
|---|---|---|
| 切在半句上 | 旧实现每 **400 词盲切**一批，模型拿到的是"从半句开始、到半句结束"的词表，看不到后文 → 必然给最后一个词收个句读 | **按静音边界切批**（`planBatches`）：攒够 200 词后遇到 >0.6s 停顿就收批；一直没停顿才放宽到 1200 词上限，且硬切前会回退到批内最后一个停顿。提示词也明确写"这是连续语音的中段，首尾可能是半句，别强行断句" |
| 断句很碎 | 切句规则里**逗号也切**（旧的 `/[,.?!…]$/`），而模型在批边界处常"保守地"插逗号 → 照样切出新句 | 切句**只认句末标点** `. ? ! …`；逗号降级为行内停顿，只有整行超 30 词 / 10 秒时才用逗号**软折**（`softFold`）。想回旧行为：`asr/settings.json` 里加 `"resegSplitOnComma": true` |
| 每词一个逗号 | 小模型把"插标点"理解成"每词后加逗号"，返回的 `[[i,","],…]` **全是合法对**，旧实现照单全收 → 几乎每词一句 | 新增**密度合理性校验**（`punctPairsSane`）：标点/词数 > 1/3、或连续 ≥4 个逗号 → 判失败重试；仍不合格就拆批，绝不把垃圾落盘 |
| 输出被截断 | `max_tokens` 不够（思考 token 也算在内）→ 半截 JSON → 解析失败，且与"模型不听话"长得一模一样 | 单独识别 `finish_reason === 'length'`：**直接拆批**（原样重试必然再失败）；单行时放大 max_tokens 再试 |

> **没配 LLM 就没有语义分句，也就没有下一步**：语义分句对所有引擎都是**必经步骤**，没有"跳过它、按引擎自带断句继续"的退路 —— 识别跑完发现 LLM 不可用时，初稿直接停在「语义分句中」并报错（错误文案写明去右上角「设置」填接口地址 / API Key / 模型名），填好点「重试」即可接着跑。「重试」对"没配 LLM"也是直接拒绝（连重试次数都不消耗，所以也不会解锁「跳过此步」）。「选区重新识别」同理：没配 LLM 直接报错，不会返回一段没分过句的结果。

### 翻译

| 现象 | 真因 | 现在 |
|---|---|---|
| "失效"且定位不到 | ① **思维链从来没剥**（全项目搜 `think` 原为 0 处）：`indexOf('[')…lastIndexOf(']')` 会被思考过程里的**示例数组**带偏；逐行兜底又把思考行算成译文行 → 行数不符 ② `max_tokens` 固定 4096 被截断 ③ `content` 为空就报"内容为空"（推理模型可能把内容放在 `reasoning_content`） ④ `fetch` **没有超时**，服务商挂起就一直等 ⑤ 429/5xx 与"内容不合规"共用一条重试阶梯，限流时递归拆半反而让请求数翻倍 | 统一收口在 `llmChat`：**剥思维链** → **平衡扫描**取第一个完整闭合的数组 → **120s 超时**（`SUBFABRIC_LLM_TIMEOUT_MS`）→ **按批量自适应 max_tokens** → **错误分型**（net/rate 指数退避并尊重 `Retry-After`；truncated 直接拆批；empty 明确说"模型只吐了思考过程"） |
| 原因看不到 | 失败细节只有 120 字，且只写进项目自己的 `draft.log` | 每次失败都 `console.error` 一条（进应用「日志」页的 SSE），带 **HTTP 状态 / finish_reason / 原始回复前 300 字**；设 `SUBFABRIC_LLM_DEBUG=1` 还会把**完整请求 + 回复**落到 `projects/<id>/llm-debug.jsonl`（默认不写，避免留痕） |

排查套路：先在「详细信息」页的日志区或应用「日志」页找 `[llm]` / `[reseg]` 开头那几行 —— 它会直接告诉你是**超时 / 限流 / 截断 / 还是模型格式跑偏**。要看原始报文就设 `SUBFABRIC_LLM_DEBUG=1` 重跑那一步。

### 每批行数（用户可调，v1.10.0）

「全局设置 → 字幕翻译 → **每批行数**」= 一次请求最多带几行给 LLM（**5~100，默认 25**）。

- 过去写死成常量 `TRANS_BATCH = 25`，用户碰不到；现在存在 `asr/settings.json` 的 `translate.batchSize`，服务端用 `llmText.clampBatchSize` 夹取（非法值/0 回落 25，1→5，9999→100）
- **权衡**：批越大请求越少、越快，但"译文行数必须与输入行数一致"这条对齐越容易整批返工，也更容易被 `max_tokens` 截断；批越小越稳、但请求数线性上升
- `max_tokens` 随批量自适应（`行数×220+512`，夹在 1024~8192），所以调大批不用手改上限
- 失败时**仍会自动拆半重试**（depth ≤ 5）—— 这个值只是"期望规模"，不是硬上限
- 两条链路都遵守它：初稿翻译（`startTranslate`）与「选区重新识别」后的翻译；切批用纯函数 `llmText.planChunks`（有单测）
- 实测 A/B（同一段 16 行音频，假 LLM 计数）：**每批 5 行 → 4 次请求（5/5/5/1）**；**每批 25 行 → 1 次请求（16 行）**

## 界面：主题色与动效（v1.11.0）

### 主题色可自定义

「设置 → 外观 → 主题色」：10 个预设色块 + 自定义取色器 + 恢复默认。设置存在**本机浏览器**（`localStorage['ss-accent']`），跟时间轴灵敏度、胶片预览那些一样属于"这台机器的偏好"，不进项目文件。

> **界面只有中文**：这个工具是给国人做双语字幕（中/英字幕轨）的，英文 UI 没有意义 —— 多语言已移除（`lang/en-US.json` 删除、设置里的「界面语言」下拉去掉）。`js/i18n.js` 保留下来的是它另一个用途：`lang/zh-CN.json` 是「键=原文、值可改」的词典，想把界面措辞改成自己的说法就直接改那个文件的值，键缺失一律回退原文。

实现要点（改这块前先看这四条）：

- **强调色只有一个来源** = `style.css` `:root` 里那一族变量：`--accent` / `--accent-2`（hover 亮一档）/ `--accent-ink`（压在主题色块上的文字色）/ `--accent-aNN`（同色透明度档 —— 组件里原先写死的 `rgba(255,122,69,α)` 已全部换成这些变量）/ `--accent-glow`。
- **`js/accent.js` 是经典脚本（不是 ES 模块）**，在 `<head>` 里**同步**执行 —— ES 模块是延迟的，首屏会先画默认橙再变紫（闪一下）。它按用户颜色重算上面那一族写到 `:root` 内联样式上；**没设过就完全不写内联样式**，「恢复默认」= 清掉内联值，不留半套残留。配色逻辑只改这一个文件。
- **`--accent-ink` 按亮度自动选深字/白字**（阈值 `lum > 0.18` 用深色 `#1a1206`，否则白字）。所有"压在主题色上"的元素（`.btn-accent`、`.btn.toggle.active`、开关滑块、`.fr-tab.active`、`.gl-tab.active`、`.badge.ass`、`.chip-l1`、占位文字）都必须用它，**不要再写死 `#1a1206`**，否则换深色主题文字就糊了。
- **主题色只管界面强调色**：字幕色（`--zh`/`--en`）、角色色、轨道色、金色警示（`.warn-toggle`/`.chip-bad`）都不跟着走 —— 那些是**语义色**，不属于主题。

### 动效

统一节拍在 `:root`：`--dur-1 .12s`（颜色反馈）/ `--dur-2 .18s`（小位移）/ `--dur-3 .26s`（面板、弹窗）/ `--dur-4 .42s`（列表入场、进度条）+ `--ease` / `--ease-out` / `--ease-back`。**别在组件里散写魔法数字**。

覆盖到的：按钮抬起/按下/主题色光晕、键盘焦点环（`:focus-visible`）、页签与设置面板切换淡入、6 个弹窗遮罩淡入 + 对话框缩放上浮、首页项目卡片**错峰入场**（`--i` 由 JS 给，上限 12 档）+ 悬停抬起、初稿进度条流光与宽度补间、"跑动中"状态呼吸、字幕卡片悬停右移与选中态、Toast 滑入滑出、日志行淡入、开关/滑块/输入框手感、设置行悬停微亮、徽标悬停放大、加载转圈（`.spin`）、首页空状态淡入、**时间轴缩放缓动**（`_zoomAtSmooth`：160ms easeOutCubic，光标下的时间保持不动，连续滚轮从当前值重新起步）。

三条自我约束：

- **只动 `transform`/`opacity`/`box-shadow`/`background`/`border-color`**，不碰宽高与位置 —— 不触发重排，长列表也不掉帧。
- **入场动画只给"整块出现"的东西**（首页项目卡片）；字幕列表（`.cue-card`）**故意只做过渡不做入场动画** —— 编辑时它反复重渲染，每次重播动画会让人烦。
- **弹窗只做进入动画，不做退出动画**：退出要等 `animationend` 再 `hidden`，会牵动所有关闭路径（Esc / 点遮罩 / 按钮），得不偿失；要加就先统一封装关闭函数。

`prefers-reduced-motion: reduce` 下**全部关闭**（动画/过渡时长压到 1e-06s、`scroll-behavior: auto`）—— 无障碍底线，不要删。

回归探针：`node tools/ui_theme_probe.mjs`（先起服务，默认 8399 端口，可用 `--` 无参直接跑）—— 真机 CDP 截图 + 断言：内联覆盖数、色块/自定义/恢复默认、按钮渐变与文字色是否跟着变、卡片错峰延迟、弹窗与面板动画名、缩放缓动有没有独立中间帧、reduced-motion 是否生效、有无 JS 报错。

### 质感层（`css/ui.css`）

`style.css` 是功能样式，**`ui.css` 是"看得见的提升"层**（在它之后加载，同选择器靠后生效）。放进去的东西：

- **设计令牌**：圆角 `--r-1..4`、投影 `--sh-1..3`、细线 `--hair/--hair-2`、面板高光 `--panel-top`、等宽字体 `--mono`。新组件优先用令牌，别再造 6px/8px/10px 混着来。
- **Chromium 滚动条**：`::-webkit-scrollbar` 系列（原来只写了 Firefox 的 `scrollbar-width`，在应用内嵌的 Chromium 里等于没写，一直是系统浅色滚动条）。
- **环境光**：`body::before` 两团极淡的主题色径向渐变，换主题时整机氛围一起变。
- **工具栏/视频区/首页卡片/侧栏字幕卡/设置面板/弹窗/Toast** 的层次与手感：渐变高光、悬停抬起、选中环、卡片左侧主题色指示条、进度条平滑增长、**Toast 四级**（成功/警告/失败/信息，图标 + 左侧色条，按文案关键词自动判级，所以 100+ 个调用点不用改）。
- **时间轴跟着主题走**：`timeline.js` 里 canvas 拿不到 CSS 变量，所以 `cssVar()` 缓存一份 `--accent`，并监听 `accent.js` 派发的 `ss-accent` 事件来更新游标/选中环。
- **图标系统**：`js/icons.js`（内联 SVG，24×24 描边风格）+ `data-ico="名字"` 声明，运行时由 `applyIcons()` 注入。emoji 在不同机器上是不同的彩色贴图，字重与基线都不受控，一排按钮混着 📁📄💾 会显得拼凑。

两条踩过的坑：

- **别给 `#home-view` 加 `position`**：它本来是 `position: fixed` 的全屏浮层（z-index 50+），改成 relative 就不盖编辑器了 —— 画面直接穿帮。要压环境光就只抬 `#app`。
- **`data-ico` 的元素里不能把图标塞进文案中间**：图标与文案必须是两个节点，i18n 按文本节点查词典；塞进中间会把文案拆开，词典匹配不上（而且视觉上也会变成图标嵌在字里）。

### 首页的刷新策略

首页列表在"有任务在跑"时**每 1.5s 全量重渲染**（让进度自己往前走）。因此：

- 卡片入场动画必须只在**进入首页**那一帧播（`elList.classList.toggle('anim-in', listAnim)`，`showHome()` 里置位），否则每 1.5s 重播一次，看着像抽搐；
- 进度条与百分比用"上次渲染到的值"做起点（`--from` + `data-from`，`countTo()` 数字滚动），这样每次重渲染是"继续走"而不是"跳一下"；
- 骨架屏（`.skel-row`）形状与真实卡片一致，避免从"一行字"到"三张卡"的布局跳动。

## 界面：二级窗口拖动 · 修复字幕入口 · 窄屏布局（v2.0.9）

### 二级窗口可拖动（`js/modal.js`）

所有标准弹窗（全局设置、查找与批量替换、通用确认、添加角色、重叠字幕选择、修复字幕、新建项目、初稿进度）都能**拖标题栏移动**，并自动限制在视口内。

- 统一入口 `bindModalDrags()`（`main.js` 启动时调一次），逐个绑定 `[遮罩, 面板, 拖动手柄]`；要新增弹窗，在 `modal.js` 的 `definitions` 里加一行即可
- 面板加 `modal-surface`、手柄加 `modal-drag-handle`；`modal-dragged` 类负责"第一次拖动时把 flex 居中换算成 fixed 的 left/top"，避免起手跳一下
- 手柄内的 `button / input / select / textarea / a` 不触发拖动（点关闭按钮不会把窗口拖走）
- 拖到视口外会被夹回（`resize` 时重新夹一次）；位置**不持久化** —— 不同分辨率下旧坐标容易越界

### 修复字幕常驻入口

字幕总览「显示模式」行新增 **🛠 修复字幕** 按钮（紧邻「↻ 刷新字幕」），选中一条 ASS 字幕后启用：

- 复用既有的单条修复链路：`openFixForRow()` → `detectRowProblems()` → `showFix()` → `fixRow()`，与时间轴右键、字幕卡片右键是同一套逻辑，**没有第二份实现**
- SRT 或未选中任何行时按钮禁用，`title` 直接说明原因（"请先选中一条 ASS 字幕"）
- 选中态变化在 `selectItem()` / `rebuildItemsAndLanes()` 里同步（`updateFixButton()`）

### 窄屏（≤ 900px）纵向布局

原来是固定三栏网格（左视频 / 右字幕栏），窗口窄到一定程度会**横向溢出**（右侧字幕栏被顶出视口）。现在：

- `#app` 用 `minmax(0, …)` 约束轨道，`#editor-panel`/`#toolbar` 补 `min-width: 0`，`.panel-head` 加 `overflow: hidden` —— 这是溢出真正的根因（grid 轨道默认 `auto` 最小尺寸由内容决定，长按钮行会把整列撑宽）
- ≤ 900px 切单列：`工具栏 → 视频 → 时间轴 → 字幕编辑区` 纵向排列，隐藏竖向分割线，页面整体纵向滚动
- 「显示模式」操作行允许换行（`flex-wrap`），按钮不会再被挤出去

## 退出程序（任务栏托盘图标）

发行版 `SubFabric.exe` 是 **GUI 子系统**（双击没有控制台窗口）：关掉浏览器页面后服务照旧在后台跑，用户根本找不到"退出这个程序"的地方，只能去任务管理器杀进程；再双击一次也只会被"端口 8321 已被占用"顶回来。

服务起来后会在**右下角托盘**放一个图标（`editor/scripts/tray.ps1`，PowerShell + WinForms，不依赖任何 npm 原生模块）：

| 操作 | 行为 |
|---|---|
| 双击图标 | 打开界面（Edge 应用模式窗口） |
| 右键 → 打开界面 | 同上 |
| 右键 → **完全退出** | `POST /api/quit` → 页面收到 `shutdown` 后补存并关掉自己的窗口 → 服务端杀掉全部子进程（ffmpeg / Python 识别 / 文件选择器）→ 关服务、断长连接、退出进程（端口随之释放）→ 托盘图标自己摘掉 |

- 首次运行会弹一次气泡提示（Windows 11 默认把新图标收进 **∧ 隐藏区**，拖出来即固定到角上；也可以在 设置 → 个性化 → 任务栏 → 其他系统托盘图标 里打开）
- 服务意外死掉（崩溃 / 被任务管理器杀掉）时，托盘图标连续 3 秒探不到端口就自己退出，不留孤儿图标
- 不想要托盘：环境变量 `SUBFABRIC_TRAY=0`（或启动参数 `--no-tray`），自动化测试用这个
- 自检（不弹窗口）：
  ```bash
  powershell -File editor/scripts/tray.ps1 -Port 8321 -SelfTest   # 建好图标/菜单后立刻收摊
  powershell -File editor/scripts/tray.ps1 -Port 8321 -QuitOnce   # 走一遍「完全退出」
  node tools/tray_quit_probe.mjs 8321                            # 真 Edge 应用窗口里验前端收尾
  ```

### 字幕列表虚拟滚动（右侧「字幕总览」卡片列表）

列表**只渲染可视窗口**（可视区上下各多留 6 行），不是把全部条目塞进 DOM。

为什么要这么做：5000 条的稿件里，真正贵的既不是建 DOM（约 65ms）也不是布局（约 300ms），
而是**绘制**——每张 `.cue-card` 的 `overflow: hidden` 都会各自生成一个裁剪容器，浏览器因此要为
5000 张卡做逐卡离屏合成，主线程被占住 **约 4.5s**（实测单次删除总卡顿 5.3s，连删一条都要重绘整表）。
只渲染可视窗口后，同样的删除降到 **约 2ms**（无长任务），视频区刷新从 3.4s 降到 96ms。

实现要点（`editor/js/editor.js`）：

- **行高实测后缓存**，不假设固定行高。缓存键是「内容指纹」（显示模式 + 两行文本 + 徽标/异常行 + 新建占位），
  同一种内容只量一张卡；删除一条时通常 0~2 条需要新量，所以日常操作不会触发全量测量。
- **高度必须取 `getBoundingClientRect()` 的小数值**。卡片真实高度是小数（`line-height: 1.3` 等），
  `offsetHeight` 会四舍五入成整数，5000 条累积下来位置表会整体偏小 30px 以上（实测 5000 条漂 32px）。
- **位置表是前缀和**，`_offsets[i]` = 第 i 条相对列表顶部的偏移；窗口靠一个 `.cue-pad` 占位块顶到正确位置，
  于是卡片自己的 `offsetTop` 仍等于它在列表里的绝对偏移，选中/行内编辑的定位逻辑不用改。
- **可见区间用矩形求交算**（spacer ∩ 列表裁剪区 ∩ 视口），两种布局共用一套公式：
  桌面布局是列表自己滚（`scrollTop`），窄屏堆叠布局是 `document.body` 整页滚。
  滚动监听挂在 `window` 的**捕获阶段**——`scroll` 不冒泡，普通监听收不到子元素滚动。
- 首次打开大稿件会有**一次性**全量量高（约 70µs/条：5000 条约 350ms，且这些卡只在隐藏容器里量、不会绘制）。
  5 万条这种极端规模下，一次性量高约 4s、位置表累积漂移约 0.004%，属于已知范围外的情况。

  - **主界面管理**：删除项目（确认后连同字幕副本/音频/波形一并删除，原始文件不动）；视频丢失的项目卡片带红虚线+⚠ 角标
  - 工具栏「🏠 项目」随时回主界面（离开前自动保存）
- **导入**：工具栏按钮或直接把视频/SRT/ASS 文件拖入视频区（支持 5GB+ 大视频，Range 流式播放）
- **SRT 双语**：每条字幕第 1 行为主语言、其余为副语言；叠加显示主上副下/副上主下可切换，字号可调；支持 `<i><b><u><font color>` 标签
- **ASS 特效（双轨结构）**：libass-wasm 渲染（卡拉OK逐词变色、\c 颜色、样式边距/对齐等）
  - 打开文件时把逐词切片**合并为整句块**，并把「整句样式句」（中文字幕）与「逐词样式句」(Default) 按时间重叠**配对成"中英双行"**条目
  - 配对原则是**归属（containment）而非"重叠最多"**：一段逐词切片只会交给**把它整段包住、且起止最贴合**的那条中文行；找不到这样的行就留成单英文行。这样**纯中文行（如 `[译者注]`、`[人群]（混乱吵架中）`）即使时间上压住/嵌进一条双语行，也不会被塞进一个英文行**，双语行自己的英文也不会被抢走。合并切片时同样做一次"归属校正"：被分组到某条行、但整批其实完全落在另一条更贴合的行的窗口里的切片，会被移交过去（只移交到验证过的收留者，绝不凭空释放，避免误伤说话人停顿造成的 0.1–0.4s 微差）
  - 右侧列表与时间轴显示干净整句（中文橙 / 英文白），视频区保持逐词特效
  - 同步生成**词级时间轴 JSON 映射**（每句每词起止时间），可经「导出词级JSON」导出
  - 编辑文本后自动重算：词数不变→保留原逐词时间；词数变化→在句内按原词时长**加权重新分配**；重建逐词切片并**立即**应用于视频区
  - 「导出干净ASS」可导出无特效整句版
- **字幕总览面板**：顶部为字幕文件名标题 + 格式徽标；胶囊搜索框（右侧圆形 🔍）；「显示模式」行右侧为 **↻ 刷新字幕** 按钮 + ⚠ 坏行过滤按钮；卡片左侧为 开始/结束/时长，右侧为 中文行 + 英文行 双行；选中卡片描边高亮；显示模式可切 中英双行/仅中文/仅英文；虚拟滚动
  - **↻ 刷新字幕**：按字幕列表里的**干净整句 + 词级时间(JSON)** 重新生成动态字幕（逐词切片）并重新应用到视频区——某些路径漏了 `update` / 渲染器没初始化好时的**手动兜底**。只修**真的不一致**的行（按 `buildWordSpecs` 期望逐项比对文本+时间；本来同步的行一个字节不动，重复点击幂等）；已知「逐词多余」类脏行**不代修**（那是 🛠 修复字幕 的职责）。SRT 则直接重灌叠加层
- **卡片配色 = 角色色**：卡片上的**所有强调色**（左侧色条、开始/结束/时长数值、中文行文字、「中文字幕」「Default」两个样式徽标）都跟着该条的**说话人颜色**走——Spoke 的行整张卡是红、Wemmbu 是紫。角色色取自 ASS 文本开头的 `{\c&H......&}`；无内联说话人色时（如 SRT、或 ASS 里没上色的行）回退成原有橙色主题。低亮度角色色（纯红 `#e50b0b`）会按亮度缺口混白提亮（`roleTone`），否则会糊进深色背景。半透明的选中/播放高亮仍是主题橙，以免"选中态"和"角色色"混淆。行内编辑器也沿用角色色
- **坏行标记（一个按钮管八类）**：⚠ 按钮实时统计坏行数并显示数量（如 `⚠ 12`）；为 0 时自动置灰禁用。点击只显示坏行，再次点击恢复全部；坏行卡片带「⚠ 坏行」黄色标签，悬停显示具体原因。判定：
  - **时间异常**：时间格式无法解析 / 结束早于开始（ASS 事件级+句子级；SRT cue 级）
  - **字幕重叠**：与其它条目时间相交（按开始时间扫描 + 当前最大结束时间，一次扫出所有相交对）
  - **英文行含方括号**：英文行里出现 `[` 或 `]`，多半是 `[人名]` 说话人标记串到英文行了
  - **单中文行 / 单英文行**：缺少配对的另一语言。ASS 用「中文/英文」措辞；SRT 按「主语言/副语言」措辞
  - **中英时间不一致**：中文整句行与英文逐词行**没有同起止**（tooltip 里给出「起 ±x.xxs 止 ±x.xxs」）。判据比的是英文**切片事件自己写在文件里的时间**，不是 `en.start/end`——后者在 `analyzeKaraoke` 分组时会被中文行(anchor)的时间直接覆盖（见 karaoke.js 第 253 行），拿它比对永远相等、永远不报。典型来源是云端识别（必剪/剪映）：首词起点常晚于句首几十毫秒，英文行整段比中文行短一截（如中文 `0.00-2.88` / 英文 `0.04-0.32`），界面上看不出、导出给别人却是错的。生成端已在 `server.js` 把首片起点贴齐句首，这一条用来兜住存量脏文件与手工改过的行
  - **未标注角色**（仅 ASS）：**中文行文本行首没有可见的 `[人物]` 标记**就算未标注——角色身份就写在文本里（视频里/列表里看到的 `[Spoke]` 就是它），所以只有 Name 栏裸名（如 `Bob`）、文本里没标记的行也判坏（画面上根本不显示角色）。刚拖出来还没输入的新行不算，一旦有文本就参与判定；从角色栏点一下角色即补上标记与颜色，坏行立刻消失
  - **英文行缺词**：英文行有逐词特效，但逐词切片数少于明文单词数（部分词丢了逐词时间）
  - **英文行重叠**：同一条英文内部有两份时间交叠的切片（复制粘贴常造成，画面上会叠字）
  - 原因可叠加（如 `字幕重叠; 单中文行(缺英文)`），tooltip 里全部列出。时间轴上坏行块带**红色虚线描边 + ⚠ 角标**（下半区英文孤行重叠也能看到）；**例外：单语孤行**——它的红虚线+⚠ 画在**空的那半**上（见下方"上下半区"），有内容的那半保持实心，否则整条行会糊成一个看不清结构的大虚线框
  - 注：反向的「逐词多余」（同一个词被重复高亮、但时间不交叠）在真实文件里很常见（示例文件里 57 行），**不并入坏行**以免淹掉徽标；交给「修复字幕」按需深度检测
- **修复字幕（右键一键检测修复）**：在**时间轴块右键菜单**或**字幕卡片右键菜单**点「🛠 修复字幕」，自动检测该行问题并弹出修复窗：
  - **无逐词效果且不与其它字幕重叠** → 自动添加逐词（在句时长内均匀铺满）
  - **英文行有角色名 `[..]` / 行首角色色标** → 删除角色名（含 Name 栏与色标），文本从词级时间轴重建，逐词高亮**校正回绿色**（避免被角色色污染）
  - **英文行逐词与文本不一致**（缺词 / 多余）**或英文行内部重复交叠** → 弹窗让用户**确认这句话到底是什么**（输入框预填检测文本），确认后按该句整体重建逐词切片（重复/交叠的脏切片一并清除）
  - 仅与其它字幕重叠的行**不**自动加逐词（重叠去逐词会丢特效，只提示）
- **列表内行内编辑（无独立编辑框）**：右栏只有字幕列表；**单击卡片的文字行**即在该文字原位进入编辑（中英双行；**光标落在你点的那一行**；`Tab` 中英互切、`回车` 直接提交、`Ctrl+回车` 分句、`Ctrl+退格` 与上一条合并、`Esc` 取消，粘贴自动转纯文本）；**新增字幕默认光标在英文区，按 `Tab` 回中文区**（见「快捷键」一节）；**点击页面其它任意位置即退出并自动保存**，实时同步左侧视频预览（ASS 逐词句改词数会按原词时长加权重算词级时间）；未改动时不写入（保留 SRT 标签等原始数据）。**单击非文字区域（时间列/空白）= 仅选中不跳转；双击非文字区域 = 跳转到该条开始时间**；双击文字不跳转（避免与进入编辑冲突）。提交时**以"正在编辑的那一条"为准**（回调显式带上条目，而不是读当前选中项）。底部仅一条细工具条（插入/删除）；时间调整走时间轴。**重建列表时保持滚动位置**（`setItems(items, keepView)` → `_applyFilter(restoreTop)`；恢复选中用 `select(item, 'keep')`，仅在完全不可见时才滚）——改时间/改文本/增删后不会跳回顶部；只有载入新文件才回到顶部
- **时间轴 · 字幕轨（单行 / 双行二选一，在「设置」里切换）**
  - **单行字幕轨（默认）**：**所有字幕都画在同一条轨道上**，不再按样式分轨；时间重叠的块就互相压着（重叠那一小块看起来更深），并被标成坏行 `字幕重叠`
  - **双行字幕轨**：把本轨按时间**重排成多条轨**——按开始时间依次放进**第一条接得上的轨**（上轨那段时间已被占，才落到下一条）；贪心 = 最少轨数，于是**每条轨内部的块互不重叠，每个块都完整可见**。注意**重叠的两块是"前者留在上轨、后者掉到下轨"**，不是两块都下去；下轨只装"被挡住"的块，轨道名标 `重叠`。**块只出现一次，不重复显示**。刻度尺/播放头/胶片条两条轨共用；轨高按剩余空间平分（不设大下限，再挤也全部装得下、不会漏到面板外）。需要几条给几条：某个时刻有 3 条以上行互相重叠时会继续加轨（正常字幕文件通常只需要 1~2 条），觉得太矮可以把「字幕块区域高度」拉大
  - 中英「同开始同结束」→ 一个**整块**（占满轨高，中间无空隙），块内**中文在上（角色色、加粗）、英文逐词轴在下**
  - **只有中文的孤行 → 只占该轨的「上半区」**；**只有英文的孤行 → 只占「下半区」**。半区高度按轨道**实际高度对半分**（`bandOf` 取真实 `laneH`，不用常量 `LANE_H`——合并轨会撑满整个面板，用常量会把「下半区」错画到轨道 1/4 处、看着仍贴在顶上）
  - 孤行的画法是**「有内容的那半 = 实心块，缺的那半 = 虚线空槽」**：实心块保持干净的整块边界（角色色描边 + 极淡填充，像一枚剪辑片段），缺的那半画虚线框——**该行记坏行时用坏行红 + ⚠**（单语行必然记坏行，于是"红虚线 = 缺另一半"一眼可读），否则用中性灰。**关键点：单语行的红虚线不再糊在实心块上**（以前两者重叠，整条行看起来像一个虚线大框，看不出"上半是实心的"）。中英都在、只是起止不同的行不画空槽。命中测试按 y 区分上下半区（`_inBand`），点上半区不会误选到下半区那条
  - **块背景 = 说话人的颜色**（半透明 45%，播放中 66%）——取自该行 ASS 文本开头的 `{\c&H......&}` 覆盖色（跳过逐词高亮的绿色），所以 Spoke=`#e50b0b` 红、Wembbu=`#ff00d0` 紫、eggchan=`#add6ff` 浅蓝、___=`#c2c2c2` 灰、Minute=白、Wraith=`#1cffff` 青……无内联色时用中性石板灰 `#5b6472`。块内文字颜色按「半透明色叠在深色轨道底后的实际亮度」自动取白/深（`textOnTranslucent`）
- **时间轴**：胶片缩略图条（真实视频帧 + 橙色时间标签）+ 橙色播放头；该轨**撑满画布剩余高度**（至少 74px = 原两轨+间隙），字幕块一直顶到面板底端
- **时间轴视图范围**：**默认跨度 30 秒**（字幕总时长不足 30s 时取字幕总时长），起点对齐**第一块**，不再一上来就铺满整个视频；**缩放上限 = 字幕第一块开始 ~ 最后一块结束**——一直缩小也只缩到刚好覆盖全部字幕，绝不超出字幕范围；平移同样被限制在这段范围内。画布变宽/变窄（改窗口大小）时保持**可见秒数**不变，不会顺带改变时间跨度
- **时间轴操作**（鼠标行为全部写死在 `timeline.js`，不可自定义）

  | 滚轮上滚 | 时间轴往前（看更早） |

  | 拖动块左/右边缘 | 改起始/结束时间，同样不与他人重叠（块宽 < 8px 时不做边缘判定） |
  | **Shift** + 拖动 | **允许重叠**；只要真的压上了，涉及的每一行**自动去掉逐词效果**（按 `main.py` 的 `remove_karaoke` 语义：英文逐词切片合并成一条干净整句，时间对齐中文行） |

    - **新建字幕（时间轴空白处拖动，或 SRT 同样路径）默认把光标放在英文区**（`panel.startEdit(ni, 2)`），**按 `Tab` 即回到中文区**继续写中文 —— 对应"先听写英文、再填中文"的实际流程。点已有卡片的文字行进编辑时，仍落在**你点的那一行**（点中文行→中文区，点英文行→英文区）
    - **`Ctrl+回车`（限英文行）= 在光标处分句**：把这一条切成两条。切点落在光标所在词之后（光标在词中间时该词归前半），**英文词级时间原样分给两半、不重算**，所以**逐词卡拉OK效果被保留**；中文按英文词数比例切开；时间切点取"前半末词的结束"与"后半首词的开始"的中点（没有词级时间时按词数比例）。光标在句首/句末（会切出空半句）时退化为普通提交，并提示"把光标放在句子中间"
    - **`Ctrl+退格`（限英文行，且光标在行首）= 与上一条合并**（纯逻辑在 `karaoke.js` 的 `mergeRowParts`，可离线单测）：
  时间取并集；**中文后段以纯文本并入上一句**（剥掉颜色/角色/高亮标签），且**中文行绝不造逐词切片** —— 
  以前这里跑 `recalcWords` + `buildWordSpecs`，中文行会被切成一条条 `{\c&H00FF00&}词{\c}`，行首角色色标也被顶掉（用户报的「合句把颜色标签一起合上去」）；
  **英文不重排已有词级时间**，只把「上一句末词的结束」接到「本句开始」补掉中间停顿，本句的词按原时间接在后面。
  实现上**就地改写上一条**、只摘掉本条 —— 不能「删掉两条再 `appendSentence`」：那个函数是在该样式最后一条事件之后插入，
  样式被删空（例如只剩这两条）会返回 null，结果两条一起消失（离线探针用 2 行文件抓到过）。
  验证：`tests/merge-row-test.mjs`（25 项纯逻辑）· `tools/merge_probe.mjs`（14 项真机：造两条带颜色的 karaoke 行 → 按 Ctrl+退格 → 解析落盘 ASS 自比）。
  已在第一条时只提示「前面没有可合并的块」，不会误删。SRT 暂不支持合并（会明确提示）。
    - 这两个动作都**先 `commitEdit()`** 把编辑框里的最新文本落盘再动结构；完成后光标回到相关行的英文区，方便连续操作
    - 注意 `startEdit/_focusLine` 的参数是**DOM 行序**（`1` = 第一个 `.ie-line` = 中文行 `ie-l1`；`2` = 英文行 `ie-l2`），不是"第几个语言"。改这两个函数或调用方时别搞反
    - `Tab` 必须在编辑器内 `preventDefault()`：否则浏览器会把焦点移出编辑器，触发 `focusout` → 还在打字就被**误提交**

## 文案与 i18n（**所有界面文字都能自己改，不用碰代码**）

`editor/lang/zh-CN.json` 是「原文 → 原文」词典：**键 = 现在的文案，值 = 你想改成的话**。改完刷新页面即生效；
键缺失、写错、删掉都只会回退到原文，界面永远不会缺字。想微调措辞就改这个文件。

**覆盖范围**（用户能看到的每一段中文都走词典）：

| 来源 | 怎么过词典 |
| --- | --- |
| `index.html` 的静态文本 / `title` / `placeholder` / `aria-label` | 启动时 `applyDom()` 扫一遍 |
| toast / 确认框 / 徽标 / 时间轴标签 / 查找替换状态 | 显示出口（`toast()`、`showConfirm()` 等）里已调 `t()` |
| **JS 拼出来的 HTML**（模型卡片说明、字幕卡角标、进度浮层…） | `MutationObserver` 在节点落地后过一遍（幂等，不会自我循环） |
| **`server.js` 的服务端消息**（草稿阶段、错误、警告） | 客户端显示时过词典（日志页逐行剥掉时间戳前缀后翻译） |
| 拼接出来的文案（`文件 · N 行 / M 句（逐词特效）`） | 源头分段调 `t()` —— 整段拼接后匹配不到任何键 |

**变量占位**：键里变量位置写成 `◇`（生成器自动归一），值里的 `◇` 要照着留 ——
例如键 `已替换 ◇ 处`，值改成 `共替换了 ◇ 处`。数字与拉丁串会被归一化匹配，所以 `已替换 12 处` 也能命中。

**不会碰的地方**（安全边界）：`contenteditable`（正在编辑的文本）、`input/textarea/select`、`canvas`、`script/style`。
设置里的**翻译提示词**是发给模型的指令，不属于界面文案，不受词典影响。

```bash
node tests/gen-lang.mjs           # 改过源码原文后重新生成词典（旧键自然失效，无需手工清理）
node tools/copy_inventory.mjs     # 导出全部用户可见文案清单（按文件+行号）→ _t/copy_inventory.md
node tools/copy_lint.mjs          # 文案自检（去 AI 味）: 破折号插入解释/客服腔/术语红线/半角标点/营销词…
node tools/copy_lint.mjs --all    # 连"提示级"一起看（省略号、日志前缀、emoji）
node tools/i18n_probe.mjs         # 真机验证: 词典覆盖率 / 动态文案生效 / 编辑框不被改写 / 不自我循环
node tools/ui_shot_walk.mjs       # 界面走查截图（21 张 → _t/shots/ + manifest.json）
```

**文案规范**（这几条是「去 AI 味」的落地约定，`copy_lint` 会盯着）：
不用破折号插入解释（`现象 —— 解释` 拆成两句）；不用「请/建议/即可」的客服腔；不用「一键/智能/轻松/高效」；
括号里只放数字、单位、英文名、快捷键；一个概念全产品一个词（识别 / 分句 / 逐词 / 降噪 / 初稿 / 打开 / 选区 / 异常行）；
按钮只写 2–4 字动词；错误消息 = 发生了什么 + 你能做什么。

## 长音频分片（云端与本地都切）

长音频两边都不友好：**云端**免费接口（必剪/剪映）对几小时的音频基本必然超时或被限流/风控；
**本地** whisper 对长音频也吃力（显存占用大、出错重来代价高）。所以超过 **25 分钟 + 1 分钟尾巴** 时自动切分：

| | 云端（必剪 / 剪映） | 本地（whisper.cpp / sherpa-onnx） |
| --- | --- | --- |
| 每片时长 | 25 分钟 | 25 分钟 |
| 切点 | **优先落在静音中点**（ffmpeg `silencedetect`，在名义切点前后 90 秒内找；找不到就用名义切点） | 同 |
| 片间关系 | 不重叠（切在静音里，不会把词切开） | 同 |
| 片间等待 | **随机 10~15 秒**（模拟人类节奏，降低风控概率） | **不等候** |
| 失败回退 | 每片各自享受「必剪 ↔ 剪映」互备 | 不涉及 |
| 超时 | 每片独立 30 分钟（不再是整段一个超时） | 同 |
| 时间戳 | 每片结果加回片起点偏移后合并（句子与逐词都加） | 同 |

**分片数据**：`projects/<id>/asr-chunks.json`（每片起止、时长、句数、实际用的引擎），
草稿元数据里另有 `draft.chunks = { count, chunkSec, source }`；日志与进度条按「第 i/N 片」显示。

短视频（≤ 25 分钟）**完全走原路径**：不做静音检测、不切片，行为与以前一致。

实现与验证：
- `editor/asr-chunks.js` —— 纯逻辑（静音解析 / 分片规划 / 偏移合并 / 串行调度，识别器可注入）
- `editor/audio-slice.js` —— 真 ffmpeg 的静音检测与切片（服务端与离线探针**共用同一份**实现）
- `tests/audio-chunk-test.mjs` —— 38 项纯逻辑（静音解析、静音优先、完整覆盖无重叠、偏移合并、边界去重、等待区间、串行与取消）
- `tools/chunk_probe.mjs` —— 18 项真 ffmpeg 离线验证（造音频 → 检静音 → 规划 → 真切片核对时长 → 假识别器 → 偏移合并；**不联网、不跑模型**）

> ⚠ 这一版**没有对真实云端做过实验**：必剪/剪映的分片链路只做了离线与逻辑验证（用户要求先不碰真实接口，
> 怕没写好被风控）。首次真机跑长音频时，建议盯着日志里的「第 i/N 片」与片间的等待。

## 说话人分离：长音频的已知风险与加固（v2.0.9+）

**识别会分片，分离不分片** —— 这是理解长视频问题的前提：上面的 25 分钟分片只作用于语音识别，
说话人分离（`asr/diarize.py`）是把整段 `audio.wav` 一次性读进内存、一次性跑完。所以时长上去时，
只有分离这一步同时吃**时间**和**内存**。

曾出现一次「长视频的说话人分离失败」，排查后确认两个**确定性隐患**（都会表现为"偶发"，因为只在长音频上触发）：

| 隐患 | 原来 | 现在 |
|---|---|---|
| 超时写死 30 分钟 | `setTimeout(kill, 30min)` 与音频多长无关 —— 长音频（尤其 CUDA 初始化失败回退 CPU 时）跑到一半被定时器杀掉，报出来的却是"退出码 1" | 上限跟随时长：`max(30min, 时长×4)`，封顶 4 小时；超时与真崩溃**分开报**（"区分说话人超时：已跑 N 分钟（上限 M 分钟）"） |
| 读音频峰值内存 | `array('h')` 副本 + `np.asarray` + `/32768.0` 各占一份，实测 **12.4 字节/采样**（3 小时音频 ≈ 2.0 GB） | `np.frombuffer` 零拷贝 + 原地归一化，实测 **6.2 字节/采样**（3 小时 ≈ 1.0 GB），**降一半**；`MemoryError` 单独捕获并给出人话提示 |

顺带修掉的诊断盲区（这些让"偶发"看起来更神秘）：

- `MemoryError` 的 `str(e)` 是**空字符串**，原来报上去只剩一个"退出码 1" —— 现在给出类型名与处置建议；
- 分离进程里的普通日志（用的 provider 是 CUDA 还是 CPU、音频多长、采样数组多大）原来只进 `pyErr` 不进报错 ——
  现在失败信息尾部带上**最后 3 行日志**，一眼能看出是不是回退了 CPU；
- 音频 ≥ 1 小时时 `diarize.py` 主动打一行提示，≥ 30 分钟时服务端把"时长 + 超时上限"写进草稿日志。

**下次再遇到分离失败，先看日志里这三样**：`provider=`（cuda 还是 cpu）、`音频 X 秒…采样数组约 Y MB`、
报错尾部的"最后日志"。是超时就按上面的人话提示处置；是内存就缩短素材或关掉分离；
是 `0xC0000005` 一类原生崩溃则多半是显卡驱动/运行库冲突，重试一次即可。

> 仍未做的：分离本身**分片**（跨片段的说话人 ID 需要用 embedding 对齐，风险较高，暂不上）。
> 所以要处理几小时素材又不急，最稳的还是先在设置里关掉「区分说话人」，出稿后再用角色功能手工分。

回归验证：`tests/diarize-wav-test.py`（需 numpy）—— 单声道/立体声/非 16k 三种输入的取值正确性，
以及新旧实现的峰值内存对比（当前断言：新实现 ≤ 7.5 字节/采样）。

> `UsePreviousAppDir`，所以**只要本机装过 SubFabric，静默安装的 `/DIR=临时目录` 就被忽略**，

> 用户数据不会被碰），但要知道自己刚把用户机器上的版本换了。真要隔离验证，得临时给
> `SubFabric.iss` 加 `UsePreviousAppDir=no` 再编一次。

**踩过的坑**：① 不跑 `fetch-vendor.js` 直接打，安装包会从 ~33.8MB 掉到 ~22.7MB（少的正是 libass worker 与 CJK 字体，字幕渲染直接废）；② `build/` 里**只有** `installer/SubFabric.iss`、`installer/start-editor.*` 与 `installer/logo.{png,ico}` 入库（.gitignore 开了例外，2026-09-30 build/ 被误删过一次），`SubFabric.exe`、`node-binary.exe`、`build/tools/rcedit-*.exe`、`editor/vendor/` 仍然不入库 —— 新克隆要跑 `fetch-vendor.js` + `build_exe.py` 生成（rcedit 会按需自动下载）；③ 版本号三处不同步，装完仍显示旧版本。

**升级要能"原地覆盖"（用户报过：每次都得手动改路径）**：`SubFabric.iss` 里有三路检测，按优先级
① Inno 自带的 `UsePreviousAppDir`（只对有卸载注册项的安装有效）→ ② 扫注册表自己的 AppId（HKLM64/HKLM32/HKCU，
键名要**去掉一层花括号**：`[Setup]` 里写成两个左花括号是转义，真实键名只有一层）→ ③ **扫盘**
（`{autopf}\SubFabric`、`{localappdata}\Programs\SubFabric`，再遍历所有盘符的
`\Program Files\SubFabric`、`\Program Files (x86)\SubFabric`、`\SubFabric`；判定条件是目录里有
`SubFabric.exe` 或 `editor\server.js`）。③ 是为**老便携版**准备的 —— 手动解压出来的目录没有任何注册记录，
① 读不到，于是每次都默认回 `C:\Program Files\...`，用户只能手动再改一遍。
检测结果在**目录页预填**（`InitializeWizard` / `CurPageChanged` 里写 `WizardForm.DirEdit.Text`，
且只在当前值仍是那个平铺默认值时才覆盖，这样命令行 `/DIR` 与 ① 都不会被顶掉）。
**页面上不要写任何说明文字**：我一开始在目录页加了句"检测到已有安装，将原地覆盖升级…"，用户反馈
"看起来明显是调试内容，别的用户看了莫名其妙" —— 检测照旧静默生效，页面文案交给 Inno 自己。

> ⚠ 两个反直觉点（都写在 .iss 注释里了）：**不要**把 `DefaultDirName` 写成 `{code:...}` 来动态决定目录 ——
> 实测它会**顶掉命令行 `/DIR`**（带 `/DIR` 的静默安装照样装去旧目录），也让 ① 失效；
> 另外静默安装（`/VERYSILENT`）**不走目录页**，所以检测只对交互式向导生效，我自己的验证流程继续用 `/DIR`。
不变量: 无孤儿事件 / 无悬空句子 / 行句一致 / 无空文本事件 / 序列化往返一致 / 切片不重叠。

**已知边界（非 bug, 属 ASS 格式固有限制）**：
- 两行**起止完全相同**时, 切片归属本质上无法从文件区分（时序完全交错）
- 文本里的 `{...}` 是 ASS 覆写标签语法, 会被解析器吃掉（含逐词高亮的词被吞 → 触发「英文行缺词」警告）
- 大部分行被去逐词后, 高亮占比跌破 30% → 逐词样式判定失效, 列表会碎成逐行
  （`analyzeKaraoke` 的判定门槛: 该样式事件 ≥6 且 >30% 含高亮切片）

## 技术要点（排障记录）

- **「编辑器开着时点另一条字幕，要点两次才进编辑」（用户报「按钮点不动」一脉的同源问题）**：`commitEdit()` 由 `document` 的 **pointerdown** 兜底触发，而 pointerdown 早于 click。旧实现在这里**同步** `closeEdit()` + `_render()`：
  - `_render()` 重建列表 DOM → `mousedown` 与 `mouseup` 落在**不同节点**上，浏览器**根本不派发 click**；
  - 即便不重建，行内编辑框是**浮层**，换行时 pointerdown 也可能落在编辑框边缘，同样凑不齐同一节点。
  改成：① `commitEdit()` 的收尾（移除编辑框 + 重建列表 + onApply）统一**延后一次事件循环**，避开本次点击；② **换行在 pointerdown 里直接做**（不等 click），并开一个约一次点击时长的"切换窗口"（`_switching`），期间任何兜底提交/焦点收尾都跳过 —— 否则旧编辑框的 `focusout` 收尾与新编辑框自己的 `focusout` 会在同一 tick 连跑，把刚建好的新编辑框连同编辑状态一起收掉；③ 延后收尾必须判**归属**（`_editGen` 代次 + `editItem` 是否仍是自己那条），过期的那次直接作废，**绝不去 closeEdit 别人的编辑框、也不把界面上的新文本写回旧行**。
- **分句/合并会丢掉逐词卡拉OK效果**：`reconcileKaraoke()` 的名字有迷惑性 —— 它**只从 `_karaokeBackup` 还原被去逐词的行，不生成逐词**。分句后两半的 `events` 仍是 `appendSentence` 建的干净整句，光设 `en.words` 不会自动变成逐词切片，序列化出去就是两句没有高亮的纯文本。必须**显式** `en.events = state.assDoc.replaceEvents(en.events, buildWordSpecs(en))`（与「新建初稿写入」「选区重新识别写回」同一条路径）。且只在 `events.length === 1` 时替换 —— 该行若由多条事件组成，直接替换会漏下多余事件变成孤儿（重复字幕）。
- **`_focusLine` / `startEdit` 的参数是 DOM 行序，不是语言序**：`1` = 第一个 `.ie-line` = **中文行** `ie-l1`；`2` = **英文行** `ie-l2`。新建字幕要"光标落在英文区"就得传 `2`（原先传 `1`，实际落在中文区，与注释"让用户马上写内容"名实不符）。
- **行内编辑器的 `Enter`/`Tab` 必须在编辑器内 `preventDefault()`**：`Tab` 不拦，浏览器会把焦点移出编辑器 → 触发 `focusout` → **还在打字就被自动提交**（新建的空行直接被撤销）。

- **「选区重新识别」按钮点不动（用户报）**：`resolveRerecogModel()` 是**模块作用域**函数，却调用了当时**定义在 `http.createServer` 请求回调里**的 `resolveDraftModel()` —— 于是每次点「🎙 重新识别」都在 `resolveRerecogModel` 里抛 `ReferenceError: resolveDraftModel is not defined`。更糟的是这个调用发生在 **POST 处理回调（异步阶段）**，`createServer` 那圈 `try/catch` 管不到它：异常被全局 `process.on('uncaughtException')` 吞成一条日志，**响应再也不会发出** → 前端 `fetch` 永不 settle，表现为"按钮点了完全没反应、连报错都没有"。修复两处：① `resolveDraftModel()` 上提到**模块作用域**（与 `resolveAsrModel` 并排，注释写明为什么必须留在那里）；② `readBody` 改为 `readBody(req, res, limit, cb)` 并在内部 `try/catch` 回调 —— 回调里抛异常就回 500 带原因、已发过响应则收尾，**任何处理器异常都不会再把请求挂死**（此前只有 `handleRequest` 的同步阶段有兜底）。现在无模型时会明确提示「语音识别模型不可用，请先在设置里下载模型」。
- **重新识别任务对象永不清理**：`rerecogJobs` 里的任务跑完仍留在 Map —— 用户**刷新页面**后重开项目，这个陈旧 job 会让下一次「重新识别」被 "已有一个重新识别任务在运行" **永久挡住**，且时间轴上的紫色进度区也不恢复（看起来白跑了）。现在：① 任务进入 done/error 时记 `finishedAt`，GET 路由对**超过 10 分钟**的已完成任务做清理；② 客户端新增 `resumeRerecog()`，打开项目时接回后台仍在跑的任务（恢复紫区 + 继续轮询取结果），由 `main.js` 经 ctx 传给 `project.js`。
- **「音频源」切换只改下次提取、播放音轨不跟着变（用户报"不能切换到原音频播放"）**：下拉的 `change` 只弹了一句"点「↻ 重新生成音频」生效"，真正切播放音轨的 `setPlaybackAudioMode()` 只在**打开项目**和**重新生成完成后**被调用 —— 于是选了「原视频」视频仍是静音的，用户以为切不动。现在 `change` 里**立刻**切播放音轨：`原视频 → setPlaybackAudioMode(null, …)`（取消静音、放视频自带原声，不必等提取）；`降噪后 →` 播项目里的降噪音轨。**"用哪条音轨播放"与"重建 audio.wav（供识别/波形）"从此是两件事**：选中的源与已提取的 `meta.audio.mode` 不一致时，提示"识别与波形仍是旧版本，要重做识别才点重新生成音频"（工具提示同步改写）。

- **双行字幕轨下新建字幕，画面上出现叠在一起的重复逐词（用户报）**：两个原因叠加。① 「新建」路径没走 Shift 拖动的重叠约定 —— 新块压在现有行上时，旧行的逐词切片还在，两行的切片同时渲染、libass 把它们叠起来。已补 `deKaraokeOverlaps()`（新建与应用文本后都调，与 Shift 拖动同一套备份/还原机制）。② `analyzeKaraoke.findAnchor` 在两条中文行**起点相同/相近**时，二分命中的是跨度更大的那条（排序按 start 再 end），切片被它抢走 → 重载后新行英文丢失、另一行词数暴涨。已改为与 `pairRows.ownerOf` 一致：在能包住切片的候选里取**跨度最小**的。

- **同一句中文字幕画面上渲染两遍（用户报，实测文件可复现）**：病灶链有两步。① 中文字幕句被切成了逐词切片（历史脏数据：样式还是「中文字幕」，切片含整句文本、当前词 `{\c&H00FF00&}词{\c}` 高亮）；② 之后一次中文整句编辑走 `applyAnchorSentence` 只改 `events[0]`，把 **1 号切片原地改写回整句**（还经"继承行首标签"逻辑捡走它的绿色标）—— 词 2..n 的切片成了无主事件留在文档里继续渲染，画面上同一句中文出现两遍；重载后这些切片各自成行（zh-only），挤在主行后面（实测文件 24.77–31.93 区间：1 锚点 + 4 切片，且锚点行首带着不该有的逐词绿标，整行发绿）。修复四层：`applyAnchorSentence` 遇 `events>1` 或 `words` 非空先把整句**折叠回单事件**再改写（折叠时剥掉切片行首的逐词绿标——说话人色永不可能是逐词绿，捡走它整行会被染绿）；`applyWordSentence` 加样式守卫——非逐词样式一律按整句折叠，函数级执行「中文行绝不造逐词切片」；`refreshDynamicSubtitles` 只对逐词样式重建切片（原先不查样式，会把带词级时间的中文句重新切片）；`setAss` 载入自愈——`ghostZhRows()`（karaoke.js 纯函数，判定从严：zh-only 单事件 + 带高亮标 + 时间被双语主行严格包住 + 文本与宿主一致或互为包含）清走幽灵行，并剥掉双语行中文行首的逐词绿标。验证：`tests/zh-ghost-heal-test.mjs`（24 项，含实测文件端到端：4 幽灵行 + 1 绿标，清走后往返行数稳定、英文 18 词切片完好）· `tools/repro_zh_doubles.mjs`（复现探针：P2 逐字节对上磁盘病灶形态）。

- **选择器不要从 stdout 取结果（用户实测报过「文件明明在却说不存在」）**：原实现把 PowerShell 的 stdout 拼成字符串当路径用，实测该通道不可靠 —— ① 换一种启动方式，PowerShell 会输出 **UTF-16LE 带 BOM**（`FF FE` 开头、ASCII 之间夹 `\0`），Node 按 UTF-8 解出来是乱码；② 用户实际遇到的更怪：路径后面被粘上 `10000 46000000` 之类杂物（`...生肉.mp4` → `...生肉.mp410000 46000000`）。现改为**结果经临时文件回传**（`[System.IO.File]::WriteAllText` 显式 UTF-8 无 BOM），stdout 直接丢弃；再加 `normalizePickedPath()` 兜底：整串不是已存在的文件时，**从后往前找「存在的最长前缀」**——只认磁盘上真实存在的文件，所以不会瞎猜；目录不做回溯（父目录必然存在，回溯会选错成上级）。项目创建接口也调一次，客户端送来的路径同样能救回来。
- **阶段交接必须清 `draftJobs`**：`startDraftAsr` 成功时不从 `draftJobs` 移除本 id（要让 `metaView` 知道任务还活着），于是 `buildDraftSubtitle` 调 `startTranslate` 时，开头的防重入 `if (draftJobs.has(id)) return;` 会**静默直接返回**——流水线卡在 88% 的「写入初稿字幕」永远不动，且不报错。交棒前必须先 `draftJobs.delete(id)`（手动触发翻译的路由同理）。
- **初稿流水线的两个坑**：① 音频是 `startPrepare` 抽的，识别必须挂在 `finishPrepare` 的成功分支后面（`pendingAsr` 里排队），不能自己在 POST 里直接起——那时 `audio.wav` 还不存在。② **`draftJobs` / `pendingAsr` 同样必须放模块作用域**，且 `metaView` 的中断修正要**两个容器都没有**才算意外中断（prepare 阶段只记在 `pendingAsr`，只查 `draftJobs` 会把正常排队中的任务误判成已中断）。
- **初稿生成的 ASS 必须走「未归属切片」路径**：Parakeet 只出英文，文件里不会有「中文字幕」锚点行，所有切片都落进 `analyzeKaraoke` 的 `loose`，靠 **>0.5s 间隔**分组成句。所以相邻句之间的停顿必须够长，否则会被并成一句。另外要防住 `evs.length < 6` 的逐词样式门槛：总词数 < 6 时切片会被当成普通整句各成一行（满屏重复），现已降级为干净整句输出。
- **服务端要存 `audio.wav`（16kHz 单声道，约 32KB/秒音频）**：长视频项目体积会明显增长，`startPrepare` 的 `peaks.pcm.tmp` 与之等大，**成功分支也必须 `cleanup()`**（原实现只在失败时清，会长期白占一份）。
- **项目系统的 `prepareJobs` 必须放模块作用域**：曾误放进 `http.createServer` 的请求回调里——每个请求都会得到一个**新的空 Set**，`metaView` 的中断修正 `!prepareJobs.has(id)` 恒真，把一切 running 中的提取误判成「服务已重启，提取被中断」（客户端随即自动补跑，波形时有时无）。同理 `readMeta` 加 3 次重试（间隔 30ms）、`writeMeta` 与字幕保存改为**临时文件+原子改名**——`sendBeacon` 兜底保存与"刷新后立刻打开"并发时，读方可能读到写了一半的 JSON/字幕。
- **项目字幕模型必须匹配逐词切片模型**：本应用的逐词 = 每个切片事件含**整句文本**、当前词用 `{\c&H00FF00&}词{\c}` 内联高亮（`HL_RE`），切片按"被哪条中文锚点行整段包住(±0.05s)"归属成组；`\k` 标签**不是**切片分隔符。另注意逐词样式判定门槛：该样式事件 **≥6 个且 >30% 含高亮切片**——构造测试字幕时每句至少 2 词 2 切片、凑满 6 事件才会触发配对。
- ASS 渲染使用 libass-wasm：`fonts`/`fallbackFont` 用**绝对路径**（worker 内以自身为基准解析相对路径会 404）。**worker/wasm/字体 URL 由 `assplayer.js` 用 `new URL('../vendor/…', import.meta.url)` 动态推导**——不要写死 `/editor/vendor/...`：`server.js` 以项目根为站点根时它成立，但若用 `python -m http.server --directory editor`（editor 目录为根）就会 404，表现为 ASS 完全不渲染（无 canvas、无报错）。动态推导在两种挂载方式下都正确。
- **`availableFonts` 不要映射缺失字体到同一文件**：worker 会为样式里声明的字体名预加载，映射后导致同一 16MB 字体重复并发下载、初始化死锁（症状：worker ready 后零消息、画布全透明）。缺失字体依靠 `fallbackFont` 自动回退即可。
- 大视频自动加载需延迟到 `window load` 之后，避免媒体流阻塞页面 load 事件。
- **列表重建会重置滚动位置**：`_applyFilter()` 里原本无条件 `listEl.scrollTop = 0`，而改时间/改文本/增删都会走 `setItems()` → 重建 → 列表**跳回顶部**，选中项被甩出虚拟列表的渲染窗口（`document.querySelector('.cue-card.selected')` 直接为 null）。排查时容易误判成"选中态丢失"。**修复**：`setItems(items, keepView)` 保留原 `scrollTop`，`_applyFilter(restoreTop)` 在新高度设好后再恢复（浏览器自动夹取）；恢复选中用 `select(item, 'keep')`——仅在完全不可见时才滚，避免编辑当下视图被拽走。载入新文件时才 `keepView=false`。
- **行内编辑器比卡片行高更高**：点中"视口上方缓冲区里那张半截卡片"时，`focus()` 会让浏览器把编辑器滚进视野（最多半屏）。这是浏览器行为，不是 bug；点在完整可见的卡片上时 `scrollTop` 全程不变。
- **单轨化后命中测试必须带 y**：同一轨道上既有整块（占满轨高）又有只占上半区/下半区的孤行，若只按时间命中，点上半区的中文行会选到下半区那条。`_hitTest` 先用二分找时间命中候选，再用 `_inBand(cue, y, laneTop, laneH)` 过滤，最后才回退到纯时间匹配。**多轨（双行字幕轨）时这套照样成立**：`_laneIndexAtY` / `_inBand` / `bandOf` 都按"第几条轨 + 轨内几何"算，所以要在下轨点中只占上半区的块，得点它**在本轨内**的上半区
- **拖动夹取只能看本轨**：`_neighbors()` 原先扫**所有**轨找前后邻居。单轨时等价，但双行字幕轨下**不同轨的块本来就允许时间重叠**（那正是分轨的目的），拿别的轨去夹会把块死死卡住、拖不过去。现在跳过不含该 cue 的轨
- **多轨平分高度不能设大下限**：双行字幕轨下轨数由数据决定（`packTracks` 贪心，正常文件 1~2 条，用户插了 5 条互相重叠的测试行就会到 5 条）。`_laneH` 若给多轨也设 74px 下限，5 条轨会撑出画布、最后一条被裁掉。现在是**单轨保持 `max(74, fill)` 原样、多轨 `floor(fill/n)` 平分**（仅留 10px 兜底）
- **重叠块的边界必须能选中（先边界、后块体）**：块重叠时，若只按"最新开始的那块在最上层"返回，被压住那块在重叠区内的起止边界就**永远拖不动**（用户报的正是这个）。`_hitTest` 现在分两步：① 候选里若有 x 距某块 start/end ≤5px 的，优先返回它；② 否则才返回 start 最大者（绘制顺序在后=视觉在最上层）。另外剪枝不能用 `cues[i].end < t` 就 break——块的 `end` 不随 `start` 单调，会漏掉"开始更早但结束更晚"的长块；`setLanes` 里预计算**前缀最大 end**（`cue._maxEnd`）用它剪枝才精确。
- **编辑提交不能读 `state.selected`**：`panel.commitEdit()` 原先只把文本交给 `onApply`，主逻辑再取 `state.selected` 落盘。但编辑期间选中项可能已被点走（→ 点时间轴会先 `onSelect` 再触发文档级 `pointerdown` 提交），结果**把 A 的文本写到了 B 身上**。修复：`commitEdit` 回调里显式带上 `item`，主逻辑以它为准、回退才用 `state.selected`。
- **滚轮/帧率别把"跟随"变成"锁死"**：跟随若不分播放状态，暂停时滚轮平移会被下一帧的跟随立刻拽回去，等于无法平移。现在只在**播放中**才把播放头拉回视野中央。
- **改窗口大小会顺带改时间跨度**：`_resize()` 只重设画布像素尺寸、`pxPerSec` 不变 → 画布变宽 = 可见秒数变多。默认视图算得早（视口还是初始宽度）时尤其明显（30s 变成 41s）。现在 `_resize` 按 `w / _lastW` 等比缩放 `pxPerSec`，保持可见秒数不变。
- **`recalcWords` 要处理"原本不是逐词句"**：刚插入/新建的行 `words` 为空，加权分配会读到 `oldDurs[-1]` → NaN 时间。`n === 0` 时改为在句内均匀铺满。
- **角色色直接当文字色会糊**：`#e50b0b`（Spoke 红）亮度只有 0.30，写在深色卡片上几乎看不清。`roleTone()` 按亮度缺口混白提亮（`#e50b0b` → `rgb(236,72,72)`），浅色角色（`#add6ff` 浅蓝、`#ffffff` 白）则原样保留。
- **字幕渲染层必须 pointer-events:none**：octopus 生成的 `.libassjs-canvas-parent` 覆盖整个视频区，只有 canvas 自身被设为 none、容器没有；一旦覆盖层拦截事件，视频区的播放/暂停/进度条点击会全部失效（字幕仍可见，极易误判为播放器状态逻辑问题）。CSS 与 AssPlayer.passThroughClicks() 双重保障。
- **改字幕起始/结束时间后逐词效果崩掉、多出重复字幕**：根因是 `fmtTimeAss` 把小数位单独 `Math.round((sec-⌊sec⌋)*100)`，遇到 `0.995~0.999` 会进位溢出成 `0:00:01.100`（3 位小数），而 ASS 小数位固定 2 位 → `parseTimeAss` 解析失败 → `_parseDialogue` 静默丢弃整条事件，但行还留在文件中 → 下一帧只替换部分行 → 残留孤儿行（重复字幕）。整体拖动时所有时间点只整体平移、小数不变，所以碰不到该边界。**修复**：`fmtTimeAss` 改为「先 `Math.round(sec*100)` 取整到厘秒再拆秒/分/时」，进位由秒字段承担（与 `main.py` 的 `format_time` 一致）；`parseTimeAss` 容错 1~3 位小数；`_parseDialogue` 对异常时间不再丢事件（夹到 0）；`replaceEvents` 行号位移改为「first 之后的所有事件」；`recalcWords`/`buildWordSpecs` 增加词级时间归一化（句内单调递增、每片 ≥1 厘秒、末词贴齐句尾，文本与词数不符时按词数均匀铺满而非塌成单条）。
- **「发行版退不干净」的根因不是窗口，是子进程 + 没有出口**（用户报）：GUI 子系统的 `SubFabric.exe` 双击后没有控制台窗口，关掉浏览器页面服务照旧在后台跑；以前唯一的"退出"是靠 `start-editor.bat` 里那句 `taskkill`（还得重新双击一次 bat），或者任务管理器。**现在**：① 托盘图标右键「完全退出」→ `POST /api/quit`；② `server.js` 把 `child_process.spawn` 包了一层**同名** `spawn`（20 多个调用点零改动），每个子进程都进 `CHILDREN` 登记表 —— 退出时 ffmpeg / Python 识别 / PowerShell 文件选择器一并收掉（只关 HTTP 服务的话，识别进程会带着几 GB 显存继续跑）；③ SSE 与媒体流是长连接，必须 `server.closeAllConnections()`，否则 `server.close()` 一直等它们自己断；④ 全链路都有超时兜底（4 秒内进程必须消失）。
- **退出的收尾顺序：先通知页面，再动手**：`shutdown()` 先 `broadcastLife('shutdown')`，600ms 后才杀子进程/关服务 —— 这 600ms 是留给页面把最后一个防抖保存用 `sendBeacon` 发出去的（前端收到事件会先手动派发一次 `beforeunload` 复用 `project.js` 的兜底保存，再 `window.close()`）。实测 Edge `--app` 窗口的 `window.close()` **生效**（217ms 关闭，`tools/tray_quit_probe.mjs` 可复现）；万一某个浏览器不让脚本关窗，页面会显示一条「已完全退出，可以关闭这个窗口了」的红条，而不是留下一个看着像卡死的界面。
- **托盘用 PowerShell + WinForms `NotifyIcon`，不是 npm 托盘库**：SEA 单文件 exe 里装不了原生模块（托盘类库都要编译原生插件），而 Windows 一定自带 `powershell.exe` 与 .NET。两个坑：① **参数不能叫 `-Pid`** —— `$PID` 是 PowerShell 只读自动变量，绑定参数会直接报错（脚本里叫 `-ServerPid`，launcher 传的也得是这个名字，传错的表现是"服务日志说托盘已就绪，但进程秒退、日志文件都不生成"）；② **`tray.ps1` 必须存成 UTF-8 带 BOM** —— PowerShell 5.1 对无 BOM 的 UTF-8 按 GBK 解，中文菜单乱码、个别字节还会让整个脚本解析失败（改完这个文件记得补 BOM）。
- **服务端退出时要跳过托盘进程**：托盘是 `server.js` 的子进程，但**不能**跟着一起强杀 —— 杀掉就没有 `NotifyIcon.Visible = $false`（NIM_DELETE），Windows 会留下一个"幽灵图标"（鼠标扫过才消失）。所以 `shutdown()` 杀子进程时 `p === trayProc` 直接 `continue`，让托盘自己收图标：托盘在「完全退出」里已经先摘图标，服务意外死掉时靠 1.5 秒一次的端口探测（连续 2 次探不到 → 摘图标退出）。
- **Windows 11 会把新托盘图标收进 `∧` 隐藏区**：系统设置里"其他系统托盘图标"默认关闭，图标不是没出来，是在溢出面板里（已实测截图确认）。所以首次运行气泡提示告诉用户"右键图标 → 完全退出、图标可以拖出来"，并把这件事写进 README —— 不去改注册表 `NotifyIconSettings` 强行置顶（那会动用户的系统设置，且不同版本键值不稳定）。
- **云端模型（必剪）在每个"按本地文件判断"的地方都要特判**：`modelReady()` 直接 `return true`（没有文件可查）、`asrGpuGateError()` 第一句就 `return null`（云端不在本机推理，与三个本地引擎"必须 GPU"的要求正好相反）、`/api/asr/status` 的 `dir/missing/filesOk` 走另一套分支（否则会被显示成"未下载"）、创建项目时的 `missingModelFiles` 校验同样跳过 —— 漏掉任何一处，表现就是"下拉里看不到它"或"创建初稿直接 400"。
- **`dirName` 为空串的坑：`POST /api/asr/delete` 差点把整个 models 目录清空**：云端模型没有目录，`modelDirFor()` 会退化成 `path.join(modelsRoot(), '')` = **模型根目录本身**，而删除接口的判据是 `dir.startsWith(modelsRoot())` → 判定为真 → `rmSync(dir, {recursive:true})` 把用户下载的所有模型一起删掉。现在删除接口对 `m.cloud` 直接 400（前端也不给「删除」按钮）；下载接口同理加拦 —— 不然 `modelFilesOk()` 会因为"没有文件清单且 sizeMB=0"直接判定"已完整"，把模型根目录当成本模型目录给"采纳"了。
- **必剪的响应字段名与剪映不是一套**（别看错）：句子文本是 `transcript`（不是 `text`）、逐词文本是 `words[].label`（不是 `word`）、时间单位是**毫秒**；而且 `data.result` 是**一层字符串**，里面才是 `{"utterances":[…]}` 的 JSON，要再 `JSON.parse` 一次。解析失败/字段缺失时打印原始片段（`toSegments`）。
- **云端识别没有子进程，取消得靠 `AbortController`**：`killDraftProc()` 原先只 kill `draftProcs` 里的子进程；云端任务是 `fetch` 挂在那里的，删项目/重跑时必须 `draftAborts.get(id).abort()`，否则旧任务会继续把音频传完、再回写一个已经删掉的项目。
- **上传前先转 16k 单声道 64kbps mp3**：项目里的 `audio.wav` 是 16k 单声道 PCM，1 小时 ≈115MB；转成 mp3 后 1 小时 ≈28MB，上传更快、流量更省（`toBcutAudio()`，临时文件在上传结束/失败后都清）。
- **只写逐词切片、没有「中文字幕」锚点行时，编辑器会按「>0.5s 间隔」重新分句**：实测必剪的 4 句（句间停顿 0.76s / 0.51s / 0.32s）在初稿阶段被并成 3 句 —— 这是既有设计（`analyzeKaraoke` 的未归属切片分组，Parakeet 初稿同样如此）；LLM 翻译写入中文锚点行后，按「归属（containment）」配对会精确还原成 4 句。所以**别把"初稿行数比 ASR 少"当成云端引擎的 bug**。
- **ASS 头署名改为按项目实际模型**：原先写死 `Generated by K-ASS-Editor draft (Parakeet TDT 0.6B v2)`，用必剪出的初稿也这么署名会误导排查；现在 `assHeader(label)` 从 `meta.draft.usedModelId || modelId` 取模型名（备份引擎生效时署的是**实际**跑的引擎）。
- **剪映云链路的关键点（自写实现，没有第三方代码可抄）**：① 请求签名是离线可算的 `MD5("9e2c|" + 路径末 7 字符 + "|" + pf + "|" + appvr + "|" + 秒级时间 + "|" + tdid + "|11ac")`，`tdid` 是免登录设备指纹（`390+年份末位` + 偶数年用 MAC 派生 / 奇数年用固定串）；② 上传位置要用临时凭证做 **AWS SigV4** 签 `ApplyUploadInner`（region=cn / service=vod、空 body、`x-amz-date;x-amz-security-token` 两个签名头）；③ 分片 PUT 带 `Content-CRC32`，随后 `POST 1:{crc32}` 报校验；④ **提交是再 PUT 一次同一份数据**（官方客户端就是这么做的，best-effort、失败不影响识别）—— 所以剪映这条链路的**上行流量约等于文件大小的两倍**，这也是上传前要先转 mp3 的原因之一；⑤ 轮询 `audio_subtitle/query` 时 **`data == null` 表示还在跑**（不是错误），出 `utterances` 才算完；⑥ 字段名与必剪**不是一套**：剪映是 `utterances[].text` / `words[].text`，必剪是 `transcript` / `words[].label`，两者时间都是毫秒。
- **两个云端引擎互为备份（`transcribeCloud`）**：免费云端普遍限次/限流，所以串起来试 —— 主引擎抛错就换另一个，日志写明「谁失败 → 换谁」。**只在云端之间回退**：本地任务绝不会被悄悄改成上传（本地模型跑不动就报错），云任务也不会退回本地模型（可能没装/没 GPU）；`signal.aborted`（用户删除项目/重跑）直接抛出、不换引擎。mp3 只转一次、换引擎复用同一个临时文件；实际生效的引擎记进 `meta.draft.usedModelId`（连带 `engine` 一起更新，排查「这份初稿是谁识别的」时要用）。
- **`model.cloud` 是个通用开关，新加云端引擎不用再到处补分支**：`modelReady` / `asrGpuGateError` / `/api/asr/status` / 创建项目校验 / 删除与下载接口守卫 / 前端设置卡片与初稿下拉，全都按 `cloud` 统一处理 —— 加剪映时只写了一个协议模块 + 一条 `ASR_MODELS` 记录 + 一条引擎表记录。**唯一必须小心的是 `dirName: ''`**：`modelDirFor()` 会退化成模型根目录（见上一条隐患）。
- **别指望"换一家云端引擎"来换断句**：两家的原始断句确实不一样（同一段 13 秒英文：必剪 4 句、剪映 5 句），但**成品断句由 LLM 语义分句统一切**（所有引擎都走），所以换家的意义只剩「限流备份」与词级时间戳的细微差别。想改断句口味就改切句规则或提示词，换引擎没用。
- **分句那几句提示词不要"顺手精简"**：`SYS_PROMPT` 里"this list is a MIDDLE SLICE of a continuous transcript … Do NOT force a sentence boundary at the very first or very last word"和"不要给每个词都加逗号"是**专门治"批边界被强行收句"和"逐词逗号"**的，删了就退回老毛病。
- **`llmChat` 是 LLM 的唯一出口**：新增任何调用方都必须走它 —— 剥思维链、平衡取 JSON、120s 超时、`finish_reason=length` 识别、错误分型、失败进应用日志，全在这一个函数里；绕过去就等于把这一整类"失效但定位不到"重新引入。它现在返回 `{content, finishReason, …}` 而不是字符串（要纯文本就 `.content`）。
- **改分句批大小要连 `planBatches` 一起看**：批边界必须落在"静音处"，这是"不切在半句上"的全部依据；`RESeg_BATCH_MAX=1200` 只是无停顿时的兜底上限，别当成目标尺寸。
- **标点密度校验是防抽风的最后一道闸**：去掉它，小模型"每词加逗号"会被当成合法结果写进字幕（几乎每词一句），而且**不报错**（那些对在语法上完全合法）—— 这类失败以前连日志都没有。
- **"每批行数"是期望规模，不是硬上限**：调大它会让"返回行数 = 输入行数"这条对齐更容易整批失败，所以**拆半重试的逻辑不能因为用户把值调小/调大就删掉**；反过来，失败时也**不要**去改用户设置（设置归用户、重试策略归程序）。
- **新写界面颜色一律走变量**：强调色用 `--accent`/`--accent-2`/`--accent-aNN`，压在强调色上的文字用 `--accent-ink`。写死 `#ff7a45` / `rgba(255,122,69,α)` / `#1a1206` 的组件，用户一换主题色就会"这一块没变"或"文字看不清" —— 主题色功能就是被这类硬编码一点点漏掉的（v1.11.0 清掉了 29 处）。
- **`js/accent.js` 不能改成 ES 模块**：它必须在首屏绘制前同步执行，否则换过主题色的用户每次打开都会看到"先橙后紫"闪一下。要加新的主题派生变量，就加在它和 `:root` 两处（分别是"运行时重算"与"默认值"）。
- **载入即自动对齐中英起止**：云端识别（必剪/剪映）给的首词起点常晚于句首（中文 0.00–2.88 / 英文 0.04–2.88），或整段英文只覆盖一小截（0.04–0.32），在 ASS 里就是"中英时间不一致"的坏行。`setAss()` 里配对完立刻跑 `autoAlignEnSpans()`：把英文逐词的时间**按比例映射到中文行的 [start,end]**（只挪时间，不动文本与高亮标签），随后自动保存写回项目。手工改坏的行走右键「🛠 修复字幕」（`detectRowProblems` 的 `spanMismatch`）。**自动那一步只碰"除起止不一致外没别的毛病"的双行**：与其它字幕重叠的行（`computeOverlapRows`）、单语行（只有中文或只有英文、没有中文锚点可对齐）、英文切片自身重叠、逐词数与文本词数不符、英文行里混进 `[角色名]` 的行 —— 全部跳过（前两类是用户明确要求"别误触"，后三类需要用户确认句子）。另：双行的块时间取自中文锚点（`karaoke.js` 的 `makeRow`），所以对齐英文词只会挪高亮时间，**不会改变任何行的起止、也不会凭空造出重叠**。**别把这一步放进 `reconcileKaraoke`**：它在每次编辑后都会跑，会把用户手动拖动首词的意图立刻抹掉。
- **角色名标签与正文之间恒为一个空格**（用户要求：`[wato] 我`，不许连着也不许两个空格）：纯函数 `normalizeRoleGap`（`karaoke.js`）—— 载入时（`normalizeAllRoleGaps`）把老文件里的 `[wato]我` / `[wato]  我` / `[wato]<tab>我` 规范成 `[wato] 我`，编辑提交时（`applyAnchorSentence` / `applyWordSentence`）再兜一遍，所以编辑框里可以随便打、落盘与显示永远是一个空格。只规范**标签与正文之间**这一处，正文内部的连续空格不动；`[]`（空标签）与行中间的方括号不认。逐词行**只改事件明文**、不重建切片 —— 重建会因为"多了一个空格"改变词数、进而触发词级时间重排，把用户的逐词时间抹掉。
- **英文分词口径必须统一在 `karaoke.js`**：`splitEnglishWords` / `splitEnglishWordsWithSpans` —— 空白 **与 `,` `.` `?` `!`** 都算分隔符，标点留在**前一个词尾**（`SMP,I plan.to` → `SMP,` `I` `plan.` `to`），于是"每遇到这类标点就逐词一次"。**三个地方必须用同一口径**：① `recalcWords`（重建词表）；② 所有"数英文词"的地方（`enTokenCount`、`detectRowProblems`、`autoAlignEnSpans` 的守卫）；③ `buildWordSpecs`（在原文本里**原位**包裹高亮）。第③处曾经自己按空白切一遍，结果 12 个词被压回 10 片、标点又黏回去（踩过：**改分词规则时，三处一起改**）。
  - **第四处（`splitRowAt` 分句）也是同一个口径**：词数必须用 `splitEnglishWords`，不能按空格数 ——
    `wood,need` 在规范分词里是**两个**词、按空格却只算一个，于是 `k` 与文本切点错位、分句会多切一个词
    （用户报的「光标在 `…my house|oh my god` 却被切成 `…my house oh / my god`」）。文本一律用 `_splitPoint`
    返回的**字符位置** `sp` 去 `slice`，这样原始空格也原样保留（`wood,need` 不会被改写成 `wood, need`）。
  - **分句/合并都不要再走「先删原行再 appendSentence」**：`appendSentence` 是在该样式最后一条事件之后插入，
    样式被删空（例如文件里只有这一条）就返回 `null`，两半/两条会一起消失。正确做法是**就地改写原行**
    （`applyAnchorSentence` / `applyWordSentence`），只给新增的那一半 append。
  - 覆盖词级时间后要**无条件重建切片**：`applyWordSentence` 自己已经重建过一次，事件数早不是 1，
    拿 `events.length === 1` 当守卫会让覆盖白做（所有词被重排）。
  - 验证：`tests/split-sentence-test.mjs`（21 项纯逻辑）· `tools/split_probe.mjs`（10 项真机：夹具用规范分词
    的原位 span 造「文本黏连、词是两个」的情形，光标放 house 之后真按 Ctrl+回车，解析落盘 ASS）。
- **动效只动 transform/opacity 这类合成属性，且必须留 `prefers-reduced-motion` 的关闭开关**；列表类容器（字幕卡片）只做过渡、不做入场动画 —— 交互频繁的列表重播动画比不动画更烦人。
