# SubFabric（字幕工作台）v1.2.3

基于 Web 的字幕编辑器：视频播放 + 字幕实时叠加 + 时间轴 + 编辑面板。
支持 **SRT 双语字幕**（主/副语言上下排列）与 **ASS 高级特效字幕**（libass 内核，卡拉OK/颜色/定位等特效完整还原）。

## 快速开始

```bash
# 1) 首次克隆后拉取渲染依赖 (libass-wasm + 中文字体, 约 19MB; 已存在则跳过)
node editor/scripts/fetch-vendor.js

# 2) 只用「创建初稿」时才需要: 建语音识别环境 (Python 3.10~3.12)
py -3.12 -m venv asr/.venv
asr/.venv/Scripts/pip.exe install -r asr/requirements.txt
#   模型本体 631MB 不入库: 首次用「创建初稿」时界面会引导你选一个空目录下载

# 3) 启动本地服务器 (支持 Range, 可直接播放本地大视频)
node editor/server.js

# 4) 浏览器打开 http://127.0.0.1:8321/  (进入项目主界面)
```

> 仓库不含示例视频与字幕（体积较大）。启动后用工具栏导入自己的视频 / SRT / ASS；
> 把媒体文件放到项目根目录，`/api/samples` 会自动列出，工具栏「示例」区一键加载。
> 旧直连 `#/editor` 仍可用（跳过主界面直接进编辑器并自动加载示例，兼容旧用法与自动化测试）。

## 功能

- **项目化（主界面）**：打开即见 **#/home 主界面**——项目卡片列表（格式徽标 ASS/SRT、视频名·字幕名·修改时间、状态角标）+「+ 新建项目」。项目数据存于 `projects/<id>/`（`project.json` 元数据 + 字幕副本 + `audio.wav` + `peaks.bin`），不影响原始视频与字幕文件
  - **新建项目 · 导入已有字幕**：选视频 + 选 SRT/ASS 字幕 → 创建后后台**一次 ffmpeg 同时提取** 16kHz 单声道音频（给后续"重新识别"铺路）与波形包络（打开项目免重新生成），完成后自动加载波形
  - **新建项目 · 创建初稿（语音识别）**：**只选视频**，服务端识别语音自动生成初稿字幕，**不用守着对话框** —— 点「开始识别」后项目立刻出现在列表里，卡片上实时显示阶段与百分比，旁边「查看进度」可展开滚动日志
    - 流程：ffmpeg 抽 16kHz 单声道音频 → Parakeet TDT 0.6B v2（sherpa-onnx）识别 → 生成字幕。识别阶段约 **15~20 倍实时**（12 秒音频实测 0.7 秒）
    - **逐词开关**：开启 → 生成 **ASS 逐词字幕**（本工具的内联高亮格式，见下）；关闭 → 生成 **SRT** 纯文本
    - 存储约定：服务端保存 `audio.wav` 与波形 `peaks.bin`，**不保存视频**（视频按路径引用）
    - 模型本体 631MB 不入库：首次用需点「选择目录…」挑一个**空目录**下载（非空目录会被拒绝，避免模型文件混进你的文件）；目录里已有完整模型则直接采纳
    - **可选识别模型**（创建初稿对话框里选，设置里可下载/删除）：
      | 模型 | 引擎 | 大小 | 说明 |
      |---|---|---|---|
      | Parakeet TDT 0.6B v2 | sherpa-onnx(CUDA) | 661MB | 英语；**必须 CUDA GPU（N 卡）**，无 N 卡 / CUDA 装不上直接报错（不支持 CPU） |
      | Whisper large-v3-turbo | whisper.cpp(Vulkan) | 1.5GB | 英语；**必须 Vulkan GPU**，A 卡/N 卡/Intel 通用，实测 RTX 4060 Ti 约 4.7 倍实时；无 Vulkan 驱动直接报错（不支持 CPU） |
      | Multitalker Parakeet Streaming 0.6B v1 | NeMo(PyTorch·CUDA) | 2.8GB | 英语·多说话人（NVIDIA NeMo 说话人核注入）。**只用于「选区重新识别」，不能创建初稿**；**只能 N 卡**，CPU 推理直接报错；还需单独安装 NeMo 运行时（PyTorch + NeMo，约 5GB） |
      - A 卡用户：官方 whisper.cpp 不发 Windows Vulkan 包，改用社区预编译版（`jerryshell/whisper.cpp-windows-vulkan-bin`），运行时在设置里一键下载（~12MB）
      - **创建初稿只列前两款**（服务端双重拦截：`modelId` 指向 Multitalker 一律 400）；Multitalker 只从「设置 → 重新识别模型」进入
      - **Multitalker 的运行时是独立的一套**：设置里的「NeMo 运行时（多说话人）」单独安装（PyTorch + NeMo，约 5GB，装在本项目的 Python 环境里）。装完会自动实测「导入 + `torch.cuda.is_available()`」才算成功 —— PyPI 上的 Windows torch 是 CPU-only 轮子（实测 2.14.0+cpu），安装器会检测到并自动换装官方 cu126 索引的 CUDA 版；Windows 上大包安装偶发 `WinError 5`（杀软扫描锁文件），安装器会自动重试
      - **该模型要装两套权重**：主权重 2.3GB + 官方流式分离权重 450MB。分离权重不是可选项 —— NeMo 的 `SpeakerTaggedASR` 即使单说话人模式也要传 `diar_model` 对象（构造函数读 `diar_model._cfg.max_num_of_spks`），缺了直接报错。单说话人行为靠 `single_speaker_mode=True` + `max_num_of_spks=1` 触发（NeMo 内部据此把 `spk_targets` 强制全 1，只跑一个 ASR 实例）
      - **该模型吃内存**：fp32 权重 2.3GB，NeMo 在 CPU 侧实例化编码器（24 层）再载入权重，峰值约 6GB 可用内存 —— 内存不够时进程会**原生崩溃（0xC0000005）而不是抛 Python 异常**，所以 `multitalker.py` 在加载前用 `GlobalMemoryStatusEx` 预检可用内存，不足直接给一句人话。GPU 侧建议 8GB 显存起
      - 实测 medium.en 在 Vulkan 上只有 0.37 倍实时（不可用），turbo 的 decoder 轻 4 倍、才是 GPU 正解
    - **仅英语**（两个模型都只对英语）；**说话人分离与 LLM 语义重分句未实现**
    - 断句只做本地基础规则：句末标点 / 停顿 > 0.8s / 行长兜底（10s 或 30 词，优先回退到逗号处）
  - **阶段文案**：项目卡片直接显示服务端给的阶段名（`STAGE`，定义在 `server.js`）——
    `提取音频中` → `ASR识别中` → `语义分句中`（仅 whisper：LLM 补标点 → 按逗号/句号切句）→ `区分说话人中` → `翻译中` → `完毕`，跑动时后面补 `...`
  - **「查看进度」弹窗**：顶部**步骤条**（`1 语音识别 · 2 说话人分离 · 3 LLM语义分句 · 4 LLM翻译 · 5 完毕`，
    当前步圆圈高亮、已过步变色）→ 进度条（完成变绿、失败变红）→ 日志区；
    左下角「跳过此步」（**语音识别与 LLM 翻译不可跳过**；说话人分离/语义分句失败重试满 3 次可跳过并继续流水线），
    右下角「重试」（LLM 步骤失败/未完成时出现）与「关闭」。项目卡片上同样有「重试」按钮
  - **字幕翻译（服务端调用 LLM）**：
    - 主界面右上角「⚙ 设置」里配置：服务商预设（DeepSeek / OpenAI / Kimi / 智谱 GLM / 通义千问 / 硅基流动 / 自定义 OpenAI 兼容）+ 接口地址 + API Key + 模型名 + 提示词，可「测试连接」；配置落在 `asr/settings.json`（不入库）
    - **触发**：设置里勾选「创建初稿后自动翻译」则识别完直接接着翻；不勾选就在项目卡片上手动点「翻译」（翻译完不会再出现该按钮）
    - **输出**：ASS 多写一轨「中文字幕」行 —— 这才是本编辑器的双语结构，与英文逐词行按时间配对成中英双行；SRT 每条 cue 写成两行（中文主语言 + 英文副语言）
    - **识别还在跑时就点「翻译」不会丢**：自动排队，识别一结束就接着翻（不会静默吞掉）
    - 每 25 行一批调用，逐批落盘 `translation.json`，中断/重启后可续翻
    - **抗模型跑偏（LLM 步骤的重点）**：模型偶发无视 JSON 要求、直接把译文一行行吐出来 —— 解析器会**容忍逐行纯文本**（去掉编号/引号/寒暄行，行数对得上就采纳），所以这类回复不再判失败
    - **升级式重试**：原提示词 → 追加「必须只输出 JSON 数组」的强化指令 → 仍失败就**把批次拆半递归**（最多拆到单行），而不是用同样的提示词原地重试（那样必然再失败）
    - **失败不回滚**：某几批失败时，已翻的行照常写进字幕，状态记成"翻译完成 x/y 行"并给出**重试按钮**；重试只补缺失的行，不会从头再来
    - 提示词默认内置一套字幕翻译规则（一对一不合并、人名地名缩写保留原文等），可在设置里改
  - **视频按路径引用**：项目只记录用户选择的视频**本地路径**，播放经 `/api/media` 按路径 Range 流式（不复制大文件）；路径失效时打开项目会弹「找不到视频文件」对话框，**重新选择视频即续用**（字幕与波形数据不受影响）
  - **字幕实时自动保存**：编辑后 1.2s 防抖自动写入项目内字幕副本（脏检查，无变化不写）；关页/刷新前 `sendBeacon` 兜底补存；工具栏实时显示「● 有未保存更改 / 保存中… / 已保存 HH:MM」——**忘了导出也不会前功尽弃**
  - **打开项目自动恢复一切**：hash 路由 `#/project/<id>` → 字幕副本、视频、波形全部就位；波形/音频未就绪（或上次被中断）会自动轮询/补跑提取
  - **主界面管理**：删除项目（确认后连同字幕副本/音频/波形一并删除，原始文件不动）；视频丢失的项目卡片带红虚线+⚠ 角标
  - 工具栏「🏠 项目」随时回主界面（离开前自动保存）
- **导入**：工具栏按钮或直接把视频/SRT/ASS 文件拖入视频区（支持 5GB+ 大视频，Range 流式播放）
- **SRT 双语**：每条字幕第 1 行为主语言、其余为副语言；叠加显示主上副下/副上主下可切换，字号可调；支持 `<i><b><u><font color>` 标签
- **ASS 特效（双轨结构）**：libass-wasm 渲染（卡拉OK逐词变色、\c 颜色、样式边距/对齐等）
  - 打开文件时把逐词切片**合并为整句块**，并把「整句样式句」（中文字幕）与「逐词样式句」(Default) 按时间重叠**配对成"中英双行"**条目
  - 配对原则是**归属（containment）而非"重叠最多"**：一段逐词切片只会交给**把它整段包住、且起止最贴合**的那条中文行；找不到这样的行就留成单英文行。这样**纯中文行（如 `[译者注]`、`[人群]（混乱吵架中）`）即使时间上压住/嵌进一条双语行，也不会被塞进一个英文行**，双语行自己的英文也不会被抢走。合并切片时同样做一次"归属校正"：被分组到某条行、但整批其实完全落在另一条更贴合的行的窗口里的切片，会被移交过去（只移交到验证过的收留者，绝不凭空释放，避免误伤说话人停顿造成的 0.1–0.4s 微差）
  - 右侧列表与时间轴显示干净整句（中文橙 / 英文白），视频区保持逐词特效
  - 同步生成**词级时间轴 JSON 映射**（每句每词起止时间），可经「导出词级JSON」导出
  - 编辑文本后自动重算：词数不变→保留原逐词时间；词数变化→在句内按原词时长**加权重新分配**；重建逐词切片并**立即**应用于视频区
  - 「导出干净ASS」可导出无特效整句版
- **字幕总览面板**：顶部为字幕文件名标题 + 格式徽标；胶囊搜索框（右侧圆形 🔍）；「显示模式」行右侧为 **↻ 刷新字幕** 按钮 + ⚠ 坏行过滤按钮；卡片左侧为 开始/结束/时长，右侧为 中文行 + 英文行 双行；选中卡片描边高亮；显示模式可切 中英双行/仅中文/仅英文；虚拟滚动
  - **↻ 刷新字幕**：按字幕列表里的**干净整句 + 词级时间(JSON)** 重新生成动态字幕（逐词切片）并重新应用到视频区——某些路径漏了 `update` / 渲染器没初始化好时的**手动兜底**。只修**真的不一致**的行（按 `buildWordSpecs` 期望逐项比对文本+时间；本来同步的行一个字节不动，重复点击幂等）；已知「逐词多余」类脏行**不代修**（那是 🛠 修复字幕 的职责）。SRT 则直接重灌叠加层
- **卡片配色 = 角色色**：卡片上的**所有强调色**（左侧色条、开始/结束/时长数值、中文行文字、「中文字幕」「Default」两个样式徽标）都跟着该条的**说话人颜色**走——Spoke 的行整张卡是红、Wemmbu 是紫。角色色取自 ASS 文本开头的 `{\c&H......&}`；无内联说话人色时（如 SRT、或 ASS 里没上色的行）回退成原有橙色主题。低亮度角色色（纯红 `#e50b0b`）会按亮度缺口混白提亮（`roleTone`），否则会糊进深色背景。半透明的选中/播放高亮仍是主题橙，以免"选中态"和"角色色"混淆。行内编辑器也沿用角色色
- **坏行标记（一个按钮管八类）**：⚠ 按钮实时统计坏行数并显示数量（如 `⚠ 12`）；为 0 时自动置灰禁用。点击只显示坏行，再次点击恢复全部；坏行卡片带「⚠ 坏行」黄色标签，悬停显示具体原因。判定：
  - **时间异常**：时间格式无法解析 / 结束早于开始（ASS 事件级+句子级；SRT cue 级）
  - **字幕重叠**：与其它条目时间相交（按开始时间扫描 + 当前最大结束时间，一次扫出所有相交对）
  - **英文行含方括号**：英文行里出现 `[` 或 `]`，多半是 `[人名]` 说话人标记串到英文行了
  - **单中文行 / 单英文行**：缺少配对的另一语言。ASS 用「中文/英文」措辞；SRT 按「主语言/副语言」措辞
  - **未标注角色**（仅 ASS）：**中文行文本行首没有可见的 `[人物]` 标记**就算未标注——角色身份就写在文本里（视频里/列表里看到的 `[Spoke]` 就是它），所以只有 Name 栏裸名（如 `Bob`）、文本里没标记的行也判坏（画面上根本不显示角色）。刚拖出来还没输入的新行不算，一旦有文本就参与判定；从角色栏点一下角色即补上标记与颜色，坏行立刻消失
  - **英文行缺词**：英文行有逐词特效，但逐词切片数少于明文单词数（部分词丢了逐词时间）
  - **英文行重叠**：同一条英文内部有两份时间交叠的切片（复制粘贴常造成，画面上会叠字）
  - 原因可叠加（如 `字幕重叠; 单中文行(缺英文)`），tooltip 里全部列出。时间轴上坏行块带**红色虚线描边 + ⚠ 角标**（下半区英文孤行重叠也能看到）；**例外：单语孤行**——它的红虚线+⚠ 画在**空的那半**上（见下方"上下半区"），有内容的那半保持实心，否则整条行会糊成一个看不清结构的大虚线框
  - 注：反向的「逐词多余」（同一个词被重复高亮、但时间不交叠）在真实文件里很常见（示例文件里 57 行），**不并入坏行**以免淹掉徽标；交给「修复字幕」按需深度检测
- **修复字幕（右键一键检测修复）**：在**时间轴块右键菜单**或**字幕卡片右键菜单**点「🛠 修复字幕」，自动检测该行问题并弹出修复窗：
  - **无逐词效果且不与其它字幕重叠** → 自动添加逐词（在句时长内均匀铺满）
  - **英文行有角色名 `[..]` / 行首角色色标** → 删除角色名（含 Name 栏与色标），文本从词级时间轴重建，逐词高亮**校正回绿色**（避免被角色色污染）
  - **英文行逐词与文本不一致**（缺词 / 多余）**或英文行内部重复交叠** → 弹窗让用户**确认这句话到底是什么**（输入框预填检测文本），确认后按该句整体重建逐词切片（重复/交叠的脏切片一并清除）
  - 仅与其它字幕重叠的行**不**自动加逐词（重叠去逐词会丢特效，只提示）
- **列表内行内编辑（无独立编辑框）**：右栏只有字幕列表；**单击卡片的文字行**即在该文字原位进入编辑（中英双行；Enter 中文→英文、英文→提交，Ctrl+Enter 提交，Esc 取消，粘贴自动转纯文本）；**点击页面其它任意位置即退出并自动保存**，实时同步左侧视频预览（ASS 逐词句改词数会按原词时长加权重算词级时间）；未改动时不写入（保留 SRT 标签等原始数据）。**单击非文字区域（时间列/空白）= 仅选中不跳转；双击非文字区域 = 跳转到该条开始时间**；双击文字不跳转（避免与进入编辑冲突）。提交时**以"正在编辑的那一条"为准**（回调显式带上条目，而不是读当前选中项）。底部仅一条细工具条（插入/删除）；时间调整走时间轴。**重建列表时保持滚动位置**（`setItems(items, keepView)` → `_applyFilter(restoreTop)`；恢复选中用 `select(item, 'keep')`，仅在完全不可见时才滚）——改时间/改文本/增删后不会跳回顶部；只有载入新文件才回到顶部
- **时间轴 · 字幕轨（单行 / 双行二选一，在「设置」里切换）**
  - **单行字幕轨（默认）**：**所有字幕都画在同一条轨道上**，不再按样式分轨；时间重叠的块就互相压着（重叠那一小块看起来更深），并被标成坏行 `字幕重叠`
  - **双行字幕轨**：把本轨按时间**重排成多条轨**——按开始时间依次放进**第一条接得上的轨**（上轨那段时间已被占，才落到下一条）；贪心 = 最少轨数，于是**每条轨内部的块互不重叠，每个块都完整可见**。注意**重叠的两块是"前者留在上轨、后者掉到下轨"**，不是两块都下去；下轨只装"被挡住"的块，轨道名标 `重叠`。**块只出现一次，不重复显示**。刻度尺/播放头/胶片条两条轨共用；轨高按剩余空间平分（不设大下限，再挤也全部装得下、不会漏到面板外）。需要几条给几条：某个时刻有 3 条以上行互相重叠时会继续加轨（正常字幕文件通常只需要 1~2 条），觉得太矮可以把「字幕块区域高度」拉大
  - 中英「同开始同结束」→ 一个**整块**（占满轨高，中间无空隙），块内**中文在上（角色色、加粗）、英文逐词轴在下**
  - **只有中文的孤行 → 只占该轨的「上半区」**；**只有英文的孤行 → 只占「下半区」**。半区高度按轨道**实际高度对半分**（`bandOf` 取真实 `laneH`，不用常量 `LANE_H`——合并轨会撑满整个面板，用常量会把「下半区」错画到轨道 1/4 处、看着仍贴在顶上）
  - 孤行的画法是**「有内容的那半 = 实心块，缺的那半 = 虚线空槽」**：实心块保持干净的整块边界（角色色描边 + 极淡填充，像一枚剪辑片段），缺的那半画虚线框——**该行记坏行时用坏行红 + ⚠**（单语行必然记坏行，于是"红虚线 = 缺另一半"一眼可读），否则用中性灰。**关键点：单语行的红虚线不再糊在实心块上**（以前两者重叠，整条行看起来像一个虚线大框，看不出"上半是实心的"）。中英都在、只是起止不同的行不画空槽。命中测试按 y 区分上下半区（`_inBand`），点上半区不会误选到下半区那条
  - **块背景 = 说话人的颜色**（半透明 45%，播放中 66%）——取自该行 ASS 文本开头的 `{\c&H......&}` 覆盖色（跳过逐词高亮的绿色），所以 Spoke=`#e50b0b` 红、Wembbu=`#ff00d0` 紫、eggchan=`#add6ff` 浅蓝、___=`#c2c2c2` 灰、Minute=白、Wraith=`#1cffff` 青……无内联色时用中性石板灰 `#5b6472`。块内文字颜色按「半透明色叠在深色轨道底后的实际亮度」自动取白/深（`textOnTranslucent`）
- **时间轴**：胶片缩略图条（真实视频帧 + 橙色时间标签）+ 橙色播放头；该轨**撑满画布剩余高度**（至少 74px = 原两轨+间隙），字幕块一直顶到面板底端
- **时间轴视图范围**：**默认跨度 30 秒**（字幕总时长不足 30s 时取字幕总时长），起点对齐**第一块**，不再一上来就铺满整个视频；**缩放上限 = 字幕第一块开始 ~ 最后一块结束**——一直缩小也只缩到刚好覆盖全部字幕，绝不超出字幕范围；平移同样被限制在这段范围内。画布变宽/变窄（改窗口大小）时保持**可见秒数**不变，不会顺带改变时间跨度
- **时间轴操作**（鼠标行为全部写死在 `timeline.js`，不可自定义）

**已知边界（非 bug, 属 ASS 格式固有限制）**：
- 两行**起止完全相同**时, 切片归属本质上无法从文件区分（时序完全交错）
- 文本里的 `{...}` 是 ASS 覆写标签语法, 会被解析器吃掉（含逐词高亮的词被吞 → 触发「英文行缺词」警告）
- 大部分行被去逐词后, 高亮占比跌破 30% → 逐词样式判定失效, 列表会碎成逐行
  （`analyzeKaraoke` 的判定门槛: 该样式事件 ≥6 且 >30% 含高亮切片）

## 技术要点（排障记录）

- **双行字幕轨下新建字幕，画面上出现叠在一起的重复逐词（用户报）**：两个原因叠加。① 「新建」路径没走 Shift 拖动的重叠约定 —— 新块压在现有行上时，旧行的逐词切片还在，两行的切片同时渲染、libass 把它们叠起来。已补 `deKaraokeOverlaps()`（新建与应用文本后都调，与 Shift 拖动同一套备份/还原机制）。② `analyzeKaraoke.findAnchor` 在两条中文行**起点相同/相近**时，二分命中的是跨度更大的那条（排序按 start 再 end），切片被它抢走 → 重载后新行英文丢失、另一行词数暴涨。已改为与 `pairRows.ownerOf` 一致：在能包住切片的候选里取**跨度最小**的。

- **选择器不要从 stdout 取结果（用户实测报过「文件明明在却说不存在」）**：原实现把 PowerShell 的 stdout 拼成字符串当路径用，实测该通道不可靠 —— ① 换一种启动方式，PowerShell 会输出 **UTF-16LE 带 BOM**（`FF FE` 开头、ASCII 之间夹 `\0`），Node 按 UTF-8 解出来是乱码；② 用户实际遇到的更怪：路径后面被粘上 `10000 46000000` 之类杂物（`...生肉.mp4` → `...生肉.mp410000 46000000`）。现改为**结果经临时文件回传**（`[System.IO.File]::WriteAllText` 显式 UTF-8 无 BOM），stdout 直接丢弃；再加 `normalizePickedPath()` 兜底：整串不是已存在的文件时，**从后往前找「存在的最长前缀」**——只认磁盘上真实存在的文件，所以不会瞎猜；目录不做回溯（父目录必然存在，回溯会选错成上级）。项目创建接口也调一次，客户端送来的路径同样能救回来。
- **阶段交接必须清 `draftJobs`**：`startDraftAsr` 成功时不从 `draftJobs` 移除本 id（要让 `metaView` 知道任务还活着），于是 `buildDraftSubtitle` 调 `startTranslate` 时，开头的防重入 `if (draftJobs.has(id)) return;` 会**静默直接返回**——流水线卡在 88% 的「写入初稿字幕」永远不动，且不报错。交棒前必须先 `draftJobs.delete(id)`（手动触发翻译的路由同理）。
- **初稿流水线的两个坑**：① 音频是 `startPrepare` 抽的，识别必须挂在 `finishPrepare` 的成功分支后面（`pendingAsr` 里排队），不能自己在 POST 里直接起——那时 `audio.wav` 还不存在。② **`draftJobs` / `pendingAsr` 同样必须放模块作用域**，且 `metaView` 的中断修正要**两个容器都没有**才算意外中断（prepare 阶段只记在 `pendingAsr`，只查 `draftJobs` 会把正常排队中的任务误判成已中断）。
- **初稿生成的 ASS 必须走「未归属切片」路径**：Parakeet 只出英文，文件里不会有「中文字幕」锚点行，所有切片都落进 `analyzeKaraoke` 的 `loose`，靠 **>0.5s 间隔**分组成句。所以相邻句之间的停顿必须够长，否则会被并成一句。另外要防住 `evs.length < 6` 的逐词样式门槛：总词数 < 6 时切片会被当成普通整句各成一行（满屏重复），现已降级为干净整句输出。
- **服务端要存 `audio.wav`（16kHz 单声道，约 32KB/秒音频）**：长视频项目体积会明显增长，`startPrepare` 的 `peaks.pcm.tmp` 与之等大，**成功分支也必须 `cleanup()`**（原实现只在失败时清，会长期白占一份）。
- **项目系统的 `prepareJobs` 必须放模块作用域**：曾误放进 `http.createServer` 的请求回调里——每个请求都会得到一个**新的空 Set**，`metaView` 的中断修正 `!prepareJobs.has(id)` 恒真，把一切 running 中的提取误判成「服务已重启，提取被中断」（客户端随即自动补跑，波形时有时无）。同理 `readMeta` 加 3 次重试（间隔 30ms）、`writeMeta` 与字幕保存改为**临时文件+原子改名**——`sendBeacon` 兜底保存与"刷新后立刻打开"并发时，读方可能读到写了一半的 JSON/字幕。
- **项目字幕模型必须匹配逐词切片模型**：本应用的逐词 = 每个切片事件含**整句文本**、当前词用 `{\c&H00FF00&}词{\c}` 内联高亮（`HL_RE`），切片按"被哪条中文锚点行整段包住(±0.05s)"归属成组；`\k` 标签**不是**切片分隔符。另注意逐词样式判定门槛：该样式事件 **≥6 个且 >30% 含高亮切片**——构造测试字幕时每句至少 2 词 2 切片、凑满 6 事件才会触发配对。
- ASS 渲染使用 libass-wasm：`fonts`/`fallbackFont` 用**绝对路径**（worker 内以自身为基准解析相对路径会 404）。**worker/wasm/字体 URL 由 `assplayer.js` 用 `new URL('../vendor/…', import.meta.url)` 动态推导**——不要写死 `/editor/vendor/...`：`server.js` 以项目根为站点根时它成立，但若用 `python -m http.server --directory editor`（editor 目录为根）就会 404，表现为 ASS 完全不渲染（无 canvas、无报错）。动态推导在两种挂载方式下都正确。
- **`availableFonts` 不要映射缺失字体到同一文件**：worker 会为样式里声明的字体名预加载，映射后导致同一 16MB 字体重复并发下载、初始化死锁（症状：worker ready 后零消息、画布全透明）。缺失字体依靠 `fallbackFont` 自动回退即可。
- 大视频自动加载需延迟到 `window load` 之后，避免媒体流阻塞页面 load 事件。
- **列表重建会重置滚动位置**：`_applyFilter()` 里原本无条件 `listEl.scrollTop = 0`，而改时间/改文本/增删都会走 `setItems()` → 重建 → 列表**跳回顶部**，选中项被甩出虚拟列表的渲染窗口（`document.querySelector('.cue-card.selected')` 直接为 null）。排查时容易误判成"选中态丢失"。**修复**：`setItems(items, keepView)` 保留原 `scrollTop`，`_applyFilter(restoreTop)` 在新高度设好后再恢复（浏览器自动夹取）；恢复选中用 `select(item, 'keep')`——仅在完全不可见时才滚，避免编辑当下视图被拽走。载入新文件时才 `keepView=false`。
- **行内编辑器比卡片行高更高**：点中"视口上方缓冲区里那张半截卡片"时，`focus()` 会让浏览器把编辑器滚进视野（最多半屏）。这是浏览器行为，不是 bug；点在完整可见的卡片上时 `scrollTop` 全程不变。
- **单轨化后命中测试必须带 y**：同一轨道上既有整块（占满轨高）又有只占上半区/下半区的孤行，若只按时间命中，点上半区的中文行会选到下半区那条。`_hitTest` 先用二分找时间命中候选，再用 `_inBand(cue, y, laneTop, laneH)` 过滤，最后才回退到纯时间匹配。**多轨（双行字幕轨）时这套照样成立**：`_laneIndexAtY` / `_inBand` / `bandOf` 都按"第几条轨 + 轨内几何"算，所以要在下轨点中只占上半区的块，得点它**在本轨内**的上半区
- **拖动夹取只能看本轨**：`_neighbors()` 原先扫**所有**轨找前后邻居。单轨时等价，但双行字幕轨下**不同轨的块本来就允许时间重叠**（那正是分轨的目的），拿别的轨去夹会把块死死卡住、拖不过去。现在跳过不含该 cue 的轨
- **多轨平分高度不能设大下限**：双行字幕轨下轨数由数据决定（`packTracks` 贪心，正常文件 1~2 条，用户插了 5 条互相重叠的测试行就会到 5 条）。`_laneH` 若给多轨也设 74px 下限，5 条轨会撑出画布、最后一条被裁掉。现在是**单轨保持 `max(74, fill)` 原样、多轨 `floor(fill/n)` 平分**（仅留 10px 兜底）
- **重叠块的边界必须能选中（先边界、后块体）**：块重叠时，若只按"最新开始的那块在最上层"返回，被压住那块在重叠区内的起止边界就**永远拖不动**（用户报的正是这个）。`_hitTest` 现在分两步：① 候选里若有 x 距某块 start/end ≤5px 的，优先返回它；② 否则才返回 start 最大者（绘制顺序在后=视觉在最上层）。另外剪枝不能用 `cues[i].end < t` 就 break——块的 `end` 不随 `start` 单调，会漏掉"开始更早但结束更晚"的长块；`setLanes` 里预计算**前缀最大 end**（`cue._maxEnd`）用它剪枝才精确。
- **编辑提交不能读 `state.selected`**：`panel.commitEdit()` 原先只把文本交给 `onApply`，主逻辑再取 `state.selected` 落盘。但编辑期间选中项可能已被点走（→ 点时间轴会先 `onSelect` 再触发文档级 `pointerdown` 提交），结果**把 A 的文本写到了 B 身上**。修复：`commitEdit` 回调里显式带上 `item`，主逻辑以它为准、回退才用 `state.selected`。
- **滚轮/帧率别把"跟随"变成"锁死"**：跟随若不分播放状态，暂停时滚轮平移会被下一帧的跟随立刻拽回去，等于无法平移。现在只在**播放中**才把播放头拉回视野中央。
- **改窗口大小会顺带改时间跨度**：`_resize()` 只重设画布像素尺寸、`pxPerSec` 不变 → 画布变宽 = 可见秒数变多。默认视图算得早（视口还是初始宽度）时尤其明显（30s 变成 41s）。现在 `_resize` 按 `w / _lastW` 等比缩放 `pxPerSec`，保持可见秒数不变。
- **`recalcWords` 要处理"原本不是逐词句"**：刚插入/新建的行 `words` 为空，加权分配会读到 `oldDurs[-1]` → NaN 时间。`n === 0` 时改为在句内均匀铺满。
- **角色色直接当文字色会糊**：`#e50b0b`（Spoke 红）亮度只有 0.30，写在深色卡片上几乎看不清。`roleTone()` 按亮度缺口混白提亮（`#e50b0b` → `rgb(236,72,72)`），浅色角色（`#add6ff` 浅蓝、`#ffffff` 白）则原样保留。
- **字幕渲染层必须 pointer-events:none**：octopus 生成的 `.libassjs-canvas-parent` 覆盖整个视频区，只有 canvas 自身被设为 none、容器没有；一旦覆盖层拦截事件，视频区的播放/暂停/进度条点击会全部失效（字幕仍可见，极易误判为播放器状态逻辑问题）。CSS 与 AssPlayer.passThroughClicks() 双重保障。
- **改字幕起始/结束时间后逐词效果崩掉、多出重复字幕**：根因是 `fmtTimeAss` 把小数位单独 `Math.round((sec-⌊sec⌋)*100)`，遇到 `0.995~0.999` 会进位溢出成 `0:00:01.100`（3 位小数），而 ASS 小数位固定 2 位 → `parseTimeAss` 解析失败 → `_parseDialogue` 静默丢弃整条事件，但行还留在文件中 → 下一帧只替换部分行 → 残留孤儿行（重复字幕）。整体拖动时所有时间点只整体平移、小数不变，所以碰不到该边界。**修复**：`fmtTimeAss` 改为「先 `Math.round(sec*100)` 取整到厘秒再拆秒/分/时」，进位由秒字段承担（与 `main.py` 的 `format_time` 一致）；`parseTimeAss` 容错 1~3 位小数；`_parseDialogue` 对异常时间不再丢事件（夹到 0）；`replaceEvents` 行号位移改为「first 之后的所有事件」；`recalcWords`/`buildWordSpecs` 增加词级时间归一化（句内单调递增、每片 ≥1 厘秒、末词贴齐句尾，文本与词数不符时按词数均匀铺满而非塌成单条）。
